# 深度讲解 · 课程制作端到端 SOP


> 制作 3:4 竖屏、有配音的深度讲解，涵盖 AI 知识、基础概念与当前热点词的教学讲解。本文是唯一端到端入口；详细规则由阶段子文档维护。


## 执行方式


1. 新选题开始时，先按 [选题规则](topic_selection.md#选题与查重) 检查完整主题词；未重复后再预留期号。恢复已有期次时，先读本文、`course/episodes.json` 和本期 `制作索引.json`，根据实际产物与已有确认记录定位当前阶段。
2. 进入每个阶段前，必须读取该阶段列出的子文档；不能只凭本文摘要执行，也不需要开工时一次读完所有技术文档。
3. 每步完成后更新本期索引的真实路径和验收事实；未生成的文件填 `null`。已有用户确认在内容未变化时继续有效，不重复询问。
4. 表中用户门禁之外的正常生成、技术检查及可自行修复问题由 AI 连续完成；明确报错，不吞异常，不静默降级。关键参数缺失、规则冲突或无法修复时再说明问题并询问。长任务完成后以独立命令核对产物，不以运行中的进度显示判断完成。
5. 主 SOP 管顺序与用户门禁，子文档管详细规则；修改规则时更新所属文档及受影响摘要，不复制整段到多个入口。历史案例不能覆盖现行规则。
6. 精简只合并重复说明，不省略“输入 → 动作 → 可检查产物 → 通过条件”。移动规则时须保留阶段入口和验收路径，不能仅凭链接仍存在就认定行为等价。

## 本期制作脚本与路径检查

- `build/` 放跨期共用的制作入口、检查器和通用工具。只服务本期的生成或修复脚本放在 `course/episodes/NN-<slug>/`，例如 `generate_visuals.py`；需要保留独立版本时放在其 `vK/` 子目录。
- 优先复用已有工具，不要求每期创建生成器。本期专用脚本随本期产物本地归档，使用现有 Git 忽略规则；跨期共用工具按仓库代码管理。
- 本仓库从第一期起在初始化和 review/publish 入口按文件名检查本期脚本位置；编辑器仍可创建文件，但错误位置会在制作开始前被阻断。

## 全流程与用户门禁

```text
主题词查重
→ 登记与选题确认
→ 写稿 → 内容审查 → 单次润色 → 事实、整幕顺读连贯性与可解析性复核
→ 整期内容与旁白切分同轮确认
→ 四幕连续配音 → 统一交付并逐幕试听确认
→ 第四幕 1 秒静音收尾 → 整期时间表
→ 固定视频风格目录 + 本期封面候选 → 用户分别选定视频风格与封面 → 同源生成 1080×1440 视频封面与 2160×2880 平台上传封面
→ 旁白语义节拍表 → 逐幕渐进构建与首次可见检查 → review → 主体运动与语义对位复核 → 用户确认审片版 vK
→ 复用已选正式封面 → 生成同版本发布文案
→ publish → 发布包验收
→ 公开发布确认 → 登记与清理
```

视频风格指全片的背景、配色、字体层级、图形语言和运动节奏。A“纸本机械”、B“技术路线”、C“明亮模块”是长期固定的三套视觉系统，统一展示于 `course/docs/video_style_presets.html`，每期直接选择，不重新生成三个候选视频。选择 A、B 或 C 同时确定“对应固定开头 + 对应风格正文”：第一幕前几秒必须原样复用所选共享开场母版；开头结束后，其控制台、框架、状态栏、刻度尺、模块位置和场景结构不得继续充当正文模板。正文只继承所选方向的配色、字体、材质、图形语言和运动节奏，并根据本期对象、关系和旁白顺序重新设计。封面仍是可独立上传的本期设计，A/B/C 分别继承同字母固定风格并独立选择；默认推荐成套，也允许“视频 A、封面 B”等跨组组合，封面选择不改变视频开头和正文风格。

**画面阶段不可省略的结果：** 默认随旁白逐步构建：从当前讲解所需的局部开始，保留仍有用的已讲内容，在讲到新信息时加入主体、连线或状态，逐渐形成完整关系。不能先摆出完整画面，再用局部移动、放大或高亮冒充信息首次出现。只有旁白确实需要先看全貌再分析时，才提前展示必要整体，并在节拍表记录对应旁白与理由；不新增用户确认门禁。选中的固定视频风格只约束正文视觉语言，不固定全片构图；正式第一幕原样复用对应共享开场母版，并按本期正式音频与 timings 完成开场及正文衔接。开头一致性和开头结束后的正文独立性必须分别验收。具体拆解、初始隐藏和验收方法见画面制作、视觉契约及渲染验收文档；lint、解码、主体停滞检测通过均不能代替首次可见与语义对位复核。

## 生产入口与完成边界

**画面对象要求：** 写稿的画面点子、封面语义元素和正式场景均须把承担解释作用的具体对象画成可识别形象，不能用名称方框替代。画面制作前在视觉节拍表记录主体及素材或绘制方式；交付前检查遮住名称后能否认出对象及其动作。详细执行见 [对象与素材规则](visual_workflow.md#具体对象的形象与素材) 和 [对象可识别性验收](render_verification.md#对象可识别性验收)，与已有技术验收共同决定是否通过。

以下命令由 AI 从项目根目录运行，替换为本期真实参数。完整参数、失败处理与检查细项见阶段子文档。

新选题登记前先检查完整主题词：

`SILICONFLOW_API_KEY` 为可选的语义提醒配置，填写在项目根目录 `.env`；不要把真实 Key 写入 `.env.example` 或其他受 Git 跟踪的文件。未配置时查重退出码为 `3`，记录语义提醒未执行后可继续；精确主题重复时退出码为 `2`，不得登记重复主题。

```bash
node --env-file-if-exists=.env build/check_course_topic_duplicate.mjs \
  --topic "候选主题" \
  --summary "准备解释的核心问题和讲解角度"
```

未发现重复后再初始化目录：

```bash
node --env-file-if-exists=.env build/init_course_episode.mjs NN-slug --topic "候选主题"
```

画面制作与局部返工时，先检查或预览受影响幕；具体区间按旁白与修改范围选择：

```bash
node --env-file-if-exists=.env build/course_video.mjs review course/episodes/NN-<slug>/制作索引.json --act 2 --check-only
node --env-file-if-exists=.env build/course_video.mjs review course/episodes/NN-<slug>/制作索引.json --act 2 --range 39:43
node --env-file-if-exists=.env build/course_video.mjs review course/episodes/NN-<slug>/制作索引.json --act 2
```

单幕定稿后由同一入口登记验收缓存；四幕齐备且前置门禁通过后，复用有效分幕生成审片版：

```bash
node --env-file-if-exists=.env build/course_video.mjs review course/episodes/NN-<slug>/制作索引.json
```

审片版本和正式封面已确认、文案就绪后，运行一次高清发布入口：

```bash
node --env-file-if-exists=.env build/course_video.mjs publish course/episodes/NN-<slug>/制作索引.json
```

publish 已包含发布包验收；后续修正文案或配套产物时，再独立执行：

```bash
node --env-file-if-exists=.env build/check_course_release.mjs course/episodes/NN-<slug>/制作索引.json
```

公开发布成功并完成登记后，先预览再清理指定期次的可重建构建产物：

```bash
node --env-file-if-exists=.env build/cleanup_course_builds.mjs --episodes 1-9
node --env-file-if-exists=.env build/cleanup_course_builds.mjs --episodes 1-9 --apply
```

清理入口的保留范围、发布状态门禁和失败行为见 [发布交付](release_delivery.md#七冻结与清理)。

- review/publish 只处理配音确认后的画面链路，不生成 VoxCPM 配音，不绕过试听、视频风格或封面选择门禁。
- `--check-only` 与 `--range` 只产出独立检查/片段预览，不登记整幕或整期完成；分幕与整期必须共用正式字幕和构建入口，避免重复渲染。缓存条件与片段限制见渲染验收文档。
- 审片与发布使用同一个 vK；发布版增加已确认的前 0.5 秒封面，不改变旁白、总时长和章节边界。默认浏览器 GPU + NVENC、每幕 2 worker、四幕串行。
- “内容制作完成 / 待发布”表示审片版已确认、正式封面仍有效且同版本文案已就绪，并由 publish 入口同步状态；“发布包就绪”还要求高清输出及完整门禁通过；“已发布”必须有公开发布成功事实。确认公开发布成功后，由助手同步台账的公开发布状态和详细状态。字段职责见发布交付文档。
- 首次输出路径可以填 `null`，入口计算目标位置，生成并检查后再登记；登记不替代用户审片确认。
- MP4 存在不代表完成；发布包必须检查通过。静态质检 HTML 可直接交付，这不豁免真实渲染及媒体验收。

## 修改后从哪里重新开始

已确认版本不能覆盖。修改影响已确认内容时，从对应阶段重新检查；未变化的确认和正式素材可复用。

| 修改内容 | 重新执行范围 |
|---|---|
| 旁白知识内容或句子 | 修改源讲解稿 → 内容审查与事实、整幕顺读连贯性、可解析性复核 → 受影响切分与用户确认 → 相关正式 JSON、配音试听及后续同步；默认润色仍只运行一次，不因返工自动反复调用 |
| 仅朗读读法或配音质量 | 定位受影响 segment，核对正式 JSON 的朗读/字幕映射，局部重配；重建受影响整轨和 timings，重新交付受影响音频试听 |
| WAV 或 timings | 核对第四幕片尾，重建整期时间表、受影响字幕/画面时长与章节文案；重新审片并输出发布版 |
| 仅视频画面 | 修正受影响画面 → 只检查/局部片段复验 → 定稿后完整渲染受影响幕 → 复用其他有效幕拼接并审片确认，再输出同一新版本的发布包；音频和 timings 未变可复用 |
| 仅封面 | 重新选择与真实渲染验收，重新输出带正式封面的高清版并验收发布包 |
| 仅发布文案 | 修正文案后重跑发布包门禁；若实际改变知识内容，回到写稿阶段 |

局部重配、版本保留、续跑及清理细则见对应阶段子文档。
