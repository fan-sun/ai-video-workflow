# 课程制作 · 讲解稿内容审查


> 本文负责讲解稿初稿完成后的内容审查。端到端顺序见 [`sop.md`](../sop.md)，概念讲解结构见 [`script_writing_explainer.md`](../teaching/script_writing_explainer.md)。

下文的完整知识结构、四幕、固定开场和配音切分要求适用于教学路线。Vibe仅复用事实、因果与指代核验、整段和跨段顺读及单次润色；观看主线、点题方式、分段及用户改稿确认按[Vibe规则](../vibe/sop.md)执行。

## 一、审查目标

内容审查回答四个问题：

1. 原始资料的主干有没有被讲全；
2. 观众能否形成完整、可复述的知识结构；
3. 四幕是否在连续推进同一个问题；
4. 新增内容是否必要、可靠，并且没有挤掉原始资料主干。

这一步不负责改善语气和口语节奏，也不负责决定配音断句。内容审查通过后才运行一次 `copy-editing`；润色后的文本完成事实、整幕顺读连贯性和可解析性复核后，再进入切分预演。

## 二、输入与结论

审查时至少读取：

- 用户提供的全部原始资料；
- 课程台账中的认知缺口、受众、核心比喻和资料边界；
- 当前完整讲解稿；
- 讲解稿引用的一手来源。

结论只允许：

- **通过**：四组检查全部满足，可以进入单次润色；
- **不通过**：明确列出缺失、偏离或断裂位置，修改源讲解稿后重新审查。

不能使用“基本通过”“后面再补”或“切分时处理”等模糊结论。

## 三、资料覆盖检查

先从原始资料提取主干，不直接从讲解稿反推。至少识别：

- 概念是什么；
- 原资料明确列出的分类、组成、阶段；
- 核心机制、因果关系或证据；
- 原资料强调的主要问题；
- 最终结论、实际价值和适用边界。

再建立以下对应关系：

| 原始资料要点 | 必须保留 | 落点 | 处理结果 |
|---|---|---|---|
| 要点原文或准确概括 | 是／否 | 第几幕、第几个场景 | 已覆盖／省略及理由 |

“必须保留”包括标题级结构、用户明确指定的重点，以及删除后会导致观众无法回答核心问题的内容。可省略次要数字、重复案例或缺少可靠出处的细节，但必须说明理由。不得因为新增内容更容易讲，就省略原资料的核心分类或核心问题。

## 四、知识结构检查

### 概念讲解

观众看完后应能回答：

- 它是什么；
- 它分为什么、由什么组成，或者有哪些关键阶段；
- 各部分如何协作或机制如何运行；
- 它面临什么主要问题；
- 它与相近概念有什么区别；
- 它有什么价值和边界。

并非每个主题都必须存在分类；原资料明确给出分类时，分类必须进入主干，不能用另一套未经确认的分类替代。

## 五、幕间连续性检查

为四幕分别写出一句“本幕回答的问题”，再检查：

| 幕 | 本幕回答什么 | 如何承接上一幕 | 如何引出下一幕 |
|---|---|---|---|
| 第一幕 |  | 无 |  |
| 第二幕 |  |  |  |
| 第三幕 |  |  |  |
| 第四幕 |  |  | 收束 |

以下情况判定为断裂：

- 相邻两幕讨论的对象发生变化，却没有解释关系；
- 新一幕重新开题，没有承接上一幕留下的问题；
- 某一幕只是资料堆积，删除后不影响整体推理；
- 结尾突然升华，不能从前文事实和机制推出；
- 场景顺序互换后几乎不影响理解，说明缺少推进关系；
- 旁白里出现空壳编号（“第一步”“第一件事”“第一，……第二，……”），删掉编号后内容和顺序都成立，说明推进关系是外加的；
- 后一幕重讲前一幕已经讲过的部件或步骤，只是换了说法；
- 把每幕末句与下一幕首句抽出来单独连读，读不通。

发现断裂时，优先调整知识顺序或删除偏题内容，不用空泛过渡句掩盖结构问题。

## 六、新增内容与边界检查

原始资料之外的分类、框架、案例、数据和结论必须同时满足：

- 有可追溯的可靠来源；
- 能直接服务已经确认的认知缺口；
- 不与原资料冲突；
- 不挤掉原始资料主干；
- 不会让观众误以为它是唯一实现或普遍事实。

只满足“相关”但不推进核心理解的内容应删除。用于解释的生活比喻可以新增，但不能改变技术含义。

## 七、直接判定不通过的情况

出现任一项即不通过：

- 核心定义、明确分类、主要问题或结论边界缺失；
- 用未经用户确认的新分类替代原资料分类；
- 主干内容没有可靠来源，或把推测写成事实；
- 四幕之间无法说明承接和推进关系；
- 前后使用同一术语表达不同含义；
- 新增内容篇幅或层级超过原始资料主干；
- 用空壳编号代替内容承接，旁白读起来像在念清单；编号后面必须跟内容名词，“第一难”“第一类失败”可以，“第一步”“第一件事”不可以；
- 幕尾落在与下一幕无关的免责、术语澄清、厂商数字或价值升华上；
- 第四幕有实质性段落重述第三幕的步骤或部件；
- 观众看完仍无法用几句话回答本期认知缺口。

## 八、单次润色规则

内容审查通过后，AI 必须完整读取项目本地 `.agents/skills/copy-editing/SKILL.md`，再对全部旁白做一次统一润色。该本地副本来源于 `coreyhaines31/marketingskills@copy-editing`，日常生产不再临时下载上游版本；只有用户明确要求升级时才更新本地副本。文件缺失或无法读取时，明确报告并停在写稿阶段，禁止静默下载新版或改用其他 Skill。

这一步只改善清晰度、语气一致性、口语节奏、具体程度和“为什么值得关心”的表达，并遵守：

- 保留原稿事实、来源、因果关系、限制条件和知识顺序；
- 概念讲解保留 [概念写稿规范](../teaching/script_writing_explainer.md) 中的“今天要学习的是 XX”固定句式和概念名称规则；
- 概念讲解保留第一幕 S0 的直接点题，不在概念名之前增加故事或悬念；
- 保留四幕结构、核心认知缺口、核心比喻和已经确认的往期视频推荐；
- 不执行面向营销转化的 CTA、销售说服或“零风险”改写，不增加原稿没有的数据、案例、经历或观点；
- 只运行一次，不再串联 `write`、`humanizer-cn` 或其他写作 Skill，也不为常规生产生成 A/B/C 版本或额外测试文档。

润色结果直接回写同一份 `course/scripts/NN-<slug>.md`，不另存一份“润色稿”。随后重新复核事实边界和知识顺序，并隐藏画面说明，将每一幕旁白连续顺读一遍；除了“为什么下一句接在这里”，还要判断编号是否多余——删掉编号后句子仍然完整、顺序仍然成立时，只修改该处并重新顺读受影响段落。四幕顺读完后再按播放顺序跨幕连读：把每幕末句与下一幕首句抽出来单独读一遍，读不通就改幕尾或幕首，不改内容顺序；幕尾改写后要重新顺读它所在的那一幕与下一幕。事实、整幕顺读连贯性和 `旁白：...` 可解析性全部通过后，AI 必须立即进入切分预演，不在讲解稿阶段单独停下来请求用户确认。

## 九、通过后的流程

审查通过后：

1. 完整读取项目本地 `.agents/skills/copy-editing/SKILL.md`；
2. 对全部旁白只运行一次统一润色；
3. 复核润色没有改变事实、证据边界、知识顺序和审查结论；
4. 隐藏画面说明，连续顺读每一幕旁白，修复无法自然承接或编号多余的位置；再按顺序跨幕连读三处接口，复核受影响的两幕；
5. 检查 `旁白：...` 结构可解析；
6. 立即生成整期旁白切分预览。

切分预览交付时，同一条消息必须提供：

- Markdown 讲解稿路径；
- 整期旁白切分预览路径；
- 资料主干覆盖摘要；
- 四幕各自回答什么以及如何连续推进的摘要；
- 明确请用户同时确认“内容”和“切分”。

用户确认前，不固定四幕正式 JSON，不生成正式配音。
