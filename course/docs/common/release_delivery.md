# 共用发布交付与归档

本文维护两条路线共同的发布包格式、文件登记、状态及授权。媒体输出、封面生成和专属文案要求由所属路线定义。


## 一、输入与交付物

审片版本 vK 已确认后，读取定稿讲解稿、制作索引和整期时间表，生成同版本发布文案，不增加文案单独用户门禁。封面按所属路线完成；主题、标题和整体视觉方向未变化时直接复用已确认图片。主顺序见 [SOP](../sop.md)。

最终五项产物为同一期、同版本的高清发布视频、独立 `cover.png`、发布文案 `.txt`、本期 `制作索引.json` 和 `course/episodes.json` 的对应记录。尚未生成的文件路径填 `null`。路径规范见 [登记文档](topic_selection.md#标准路径与目录初始化)。

制作索引的 `review_output`、`publish_output`、`cover_output` 分别指向实际审片版、高清发布版和正式封面；封面行为按所属路线记录，媒体规格使用结构化 `publish_spec`。台账 `output` 只记录已生成并通过解码及时长检查的当前版本成片，不预填尚未生成的发布版路径；登记不代表用户已经确认审片或公开发布。

## 二、发布文案格式

所有新期次的同一个 `.txt` 固定包含以下区块，顺序不能改变：

```text
【标题】
【发布文案】
【标签】
【视频总结】
【视频章节】
```

`【发布文案】` 面向平台传播，可使用提问、反差和观看理由。标签固定在视频总结前，具体标签与标题写法由所属路线维护。

`【视频总结】` 是可独立阅读的内容说明，不以“本期介绍了”“这段视频讲了”等创作者复述代替内容，也不把讲解结构当作总结。建议 80～150 字，门禁允许 50～200 个非空白字符；不得包含标签、章节时间或互动号召，不照抄发布文案。助手随文案一次生成，不另建文件、生成器或独立审批；实际内容取舍按路线标准。

## 三、章节标题与时间

章节使用观众可理解的内容短标题，优先不超过 7 个汉字，不用内部编号、空泛“第一部分”或完整句。标题只维护在制作索引 chapter_titles，无首尾空白；按正式整期时间表的实际幕数和累计边界四舍五入到整秒。视频是否显示章节及显示方式由所属路线决定。下面仅以四幕举例：

```text
【视频章节】

00:00–00:50　第一幕 · <观众可读标题>
00:50–02:01　第二幕 · <观众可读标题>
02:01–03:14　第三幕 · <观众可读标题>
03:14–04:41　第四幕 · <观众可读标题>
```


本仓库所有新期次章节标题在 review 前写入制作索引并定稿；时间范围不得提前估算。所属路线正式时间信息变化后，必须先重建整期时间表，再更新发布文案及所属路线的视频内进度。发布前核对：高清发布版、独立封面、发布配套文案、`制作索引.json` 和 `episodes.json` 的期号、主题、版本与时长一致。

## 四、高清输出与状态

用户已确认审片版、正式封面仍有效且同版本发布文案就绪后，内容制作状态才完成。随后首次运行 publish 入口时，入口会核验已存在的 `cover_selection` 与 `cover.png`，并幂等同步同期期次的 `dashboard_status="待发布"`、`publish_status="未发布"`；详细生产 `status` 继续反映高清构建与发布包验收进度。公开发布确认前不得把任一字段写为“已发布”。


status 记录详细生产阶段，dashboard_status 保留为简短阶段字段，publish_status 记录是否公开发布。三者由本仓库 JSON 台账维护；notes 记录制作过程、用户选择及验收事实，不重复保存会变化的当前状态。

封面选定只完成封面门禁，不表示全部画面已经完成；首次 publish 会在审片确认、封面和文案均就绪后同步待发布状态，之后才按路线生成发布文件并验收。因此“待发布”不代表发布包已通过，只有完整门禁成功才算发布包就绪。已有“已发布”状态不得回退。

AI 运行所属路线 SOP 的发布命令，按所属路线生成同版本发布文件；媒体输出方法见所属路线 SOP，公共检查与缓存方法见[渲染验收](render_verification.md)。

首次 review 的 `review_output`、首次 publish 的 `publish_output` 可以为 `null`。入口按期号、slug 和版本在内存中计算标准输出位置，不提前回写；publish 仍要求已经存在的审片输入和正式封面。

最终视频完整解码、文件与时长检查通过后，入口先登记对应的真实输出路径，再执行发布包验收。`publish_spec.duration_s` 和台账 `duration_s` 取正式 `整期时间表.json.total_s`，实际 MP4 时长须在允许容差内；台账同时更新当前版本，但保留详细生产状态、公开发布状态和备注。同版本已有有效发布输出时，重跑 review 只登记审片路径，保留台账发布路径与发布规格。生成、解码或时长检查失败时不登记新输出；后续发布包检查失败时，真实文件记录可以保留，但不算发布包完成。

## 五、发布包验收

五项产物就绪后，AI 必须运行所属路线的发布检查命令，不要求用户执行。路线命令调用下列共同底层门禁；输出归属按[共用输出规则](output_paths.md)：

```bash
node --env-file-if-exists=.env build/common/check_course_release.mjs course/episodes/NN-<slug>/制作索引.json
```

命令失败时，AI 必须根据错误信息补齐或修正产物并自动重跑，不能把命令转交给用户。只有命令返回 0 并显示“发布包检查通过”，该版本才可进入发布确认。高清发布版单独生成不代表发布包完成；命令会拦截缺失文件、跨版本文案、标签顺序或所属路线标签错误、视频总结缺失或不合规、章节时间或标题不一致、实际媒体规格或时长不符、全片解码失败、审片与发布音频不一致，以及制作索引和课程台账不一致。路线专属媒体验收及封面门禁由所属路线执行。公开发布仍必须单独获得用户授权。


publish 入口已包含此检查；入口已通过且所有输入输出未变时，不额外重复同一轮完整验收。修正文案、封面或索引等配套产物后必须重新执行独立门禁。

## 六、公开发布与登记

发布包检查通过后，才进入公开发布确认。公开发布是外部操作，必须获得用户明确授权；已获授权不重复询问。不能把“同意发布”当作“发布成功”。用户确认已经成功公开发布后，由 AI 或[视频状态看板](published_cleanup.md)同步台账字段 dashboard_status="已发布"、publish_status="已发布" 和 status="Vn 已公开发布"。记录确认依据；实际平台、发布日期只有用户提供或有事实依据时才填写，不能把确认日期冒充发布日期。

用户确认已经公开发布后，AI 同步向 `course/published-videos.json` 新增或更新本期条目。目录只记录已发布课程，至少保存 `episode`、`topic`、`recommendation_name`、一段可独立阅读的 `summary`、用于关联判断的 `keywords`，以及制作索引、发布文案和发布视频路径。以 `episode` 为唯一键幂等更新；发布包就绪但尚未公开发布时禁止提前登记。


## 七、冻结与清理

公开发布并固定版本后，进入[共同保留与清理流程](published_cleanup.md)，再按所属路线的重建输入文档核对依赖。删除条件、原件保留、候选预览命令和暂停状态只在共同清理规范维护，本文件不另设清单。
