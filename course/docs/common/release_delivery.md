# 课程制作 · 发布交付与归档

本文的配音、固定课程标签、0.5秒封面与片尾静音要求适用于教学路线。`route: "vibe"`的发布文案、独立封面和声音按[Vibe交付规则](../vibe/sop.md#5-独立封面与发布文案)执行；两条路线使用同一个publish/check入口，按索引route分别验收。


## 一、输入与交付物

审片版本 vK 已确认后，读取定稿讲解稿、制作索引和整期时间表，生成同版本发布文案，不增加文案单独用户门禁。教学封面按 [教学封面流程](../teaching/cover_workflow.md) 选定，Vibe按 [独立封面流程](../vibe/cover_workflow.md) 完成；主题、标题和整体视觉方向未变化时直接复用已确认图片。主顺序见 [SOP](../sop.md)。

最终五项产物为同一期、同版本的高清发布视频、独立 `cover.png`、发布文案 `.txt`、本期 `制作索引.json` 和 `course/episodes.json` 的对应记录。尚未生成的文件路径填 `null`。路径规范见 [登记文档](topic_selection.md#标准路径与目录初始化)。

制作索引的 `review_output`、`publish_output`、`cover_output` 分别指向实际审片版、高清发布版和正式封面；教学的`cover_embed.duration_s`为`0.5`，Vibe为`0`，媒体规格使用结构化 `publish_spec`。台账 `output` 只记录已生成并通过解码及时长检查的当前版本成片，不预填尚未生成的发布版路径；登记不代表用户已经确认审片或公开发布。

## 二、发布文案格式

所有新期次的同一个 `.txt` 固定包含以下区块，顺序不能改变：

```text
【标题】
【发布文案】
【标签】
【视频总结】
【视频章节】
```

`【发布文案】` 面向平台传播，可以使用提问、认知反差和观看理由。所有新期次，`【标签】` 固定放在 `【视频总结】` 前；教学线必须包含三个独立标签 `#AI`、`#AI基础`、`#深度讲解`，允许继续添加本期主题标签，但 `#AI基础` 不能替代独立的 `#AI`，带前后缀的长标签也不能替代对应固定标签。Vibe标签及总结内容按其SOP，不套用教学固定标签或知识覆盖框架。`【视频总结】` 面向用户提供一段可独立阅读的内容说明。教学概念讲解应直接回答“它是什么、为什么重要、有什么必要边界”。不得使用“本期介绍了”“这段视频讲了”等创作者复述视角，也不能把讲解结构当成知识总结。总结建议 80～150 字，门禁允许 50～200 个非空白字符；不得包含标签、章节时间或互动号召，也不能照抄发布文案。总结由 AI 随同发布文案一次生成，不增加独立文件或单独生成器。所有期次均执行视频总结及所属路线的标签要求。


## 三、章节标题与时间

章节使用观众能直接理解的内容短标题，不使用内部编号或空泛的“第一部分”。本仓库所有新期次，标题写成几个词，优先不超过 7 个汉字，不写完整句。标题只保存在本期 `制作索引.json` 的 `chapter_titles`，不能带首尾空白。教学线的视频内章节栏逐字共用这些标题，显示不下时仅画面省略，发布文案保留全称，详见[视频内章节进度条](../teaching/video_chapter_progress.md)；Vibe只按实际幕数生成发布文案章节，不要求视频覆盖栏。教学线在正式音频和整期时间表生成后、Vibe在视觉时间表生成后，读取每幕累计边界并四舍五入到整秒。下面以四幕为例：

```text
【视频章节】

00:00–00:50　第一幕 · <观众可读标题>
00:50–02:01　第二幕 · <观众可读标题>
02:01–03:14　第三幕 · <观众可读标题>
03:14–04:41　第四幕 · <观众可读标题>
```


本仓库所有新期次章节标题在 review 前写入制作索引并定稿；时间范围不得提前估算。教学timings或Vibe视觉时间变化后，必须先重建整期时间表，再更新发布文案及所属路线的视频内进度。发布前核对：高清发布版、独立封面、发布配套文案、`制作索引.json` 和 `episodes.json` 的期号、主题、版本与时长一致。

## 四、高清输出与状态

用户已确认审片版、正式封面仍有效且同版本发布文案就绪后，内容制作状态才完成。随后首次运行 publish 入口时，入口会核验已存在的 `cover_selection` 与 `cover.png`，并幂等同步同期期次的 `dashboard_status="待发布"`、`publish_status="未发布"`；详细生产 `status` 继续反映高清构建与发布包验收进度。公开发布确认前不得把任一字段写为“已发布”。


status 记录详细生产阶段，dashboard_status 保留为简短阶段字段，publish_status 记录是否公开发布。三者由本仓库 JSON 台账维护；notes 记录制作过程、用户选择及验收事实，不重复保存会变化的当前状态。

封面选定只完成封面门禁，不表示四幕画面已经完成；首次 publish 会在审片确认、封面和文案均就绪后同步待发布状态，之后才构建高清并验收。因此“待发布”不代表发布包已通过，只有完整门禁成功才算发布包就绪。已有“已发布”状态不得回退。

AI 运行 `node --env-file-if-exists=.env build/common/course_video.mjs publish course/episodes/NN-<slug>/制作索引.json`，输出同版高清；调用条件、GPU 串行、音轨复制和安全续跑见 [渲染验收](render_verification.md)。

首次 review 的 `review_output`、首次 publish 的 `publish_output` 可以为 `null`。入口按期号、slug 和版本在内存中计算标准输出位置，不提前回写；publish 仍要求已经存在的审片输入和正式封面。

最终视频完整解码、文件与时长检查通过后，入口先登记对应的真实输出路径，再执行发布包验收。`publish_spec.duration_s` 和台账 `duration_s` 取正式 `整期时间表.json.total_s`，实际 MP4 时长须在允许容差内；台账同时更新当前版本，但保留详细生产状态、公开发布状态和备注。同版本已有有效发布输出时，重跑 review 只登记审片路径，保留台账发布路径与发布规格。生成、解码或时长检查失败时不登记新输出；后续发布包检查失败时，真实文件记录可以保留，但不算发布包完成。

## 五、发布包验收

五项产物就绪后，AI 必须从项目根目录自动运行门禁，不要求用户执行命令：

```bash
node --env-file-if-exists=.env build/common/check_course_release.mjs course/episodes/NN-<slug>/制作索引.json
```

命令失败时，AI 必须根据错误信息补齐或修正产物并自动重跑，不能把命令转交给用户。只有命令返回 0 并显示“发布包检查通过”，该版本才可进入发布确认。高清发布版单独生成不代表发布包完成；命令会拦截缺失文件、跨版本文案、标签顺序或所属路线标签错误、视频总结缺失或不合规、章节时间或标题不一致、实际媒体规格或时长不符、全片解码失败、审片与发布音频不一致，以及制作索引和课程台账不一致。教学线另检查片尾静音、0–0.5秒封面稳定及0.5秒后封面消失，并分别记录固定视频风格与封面选择，按需生成的第二轮封面构图仍等待用户选择；Vibe按独立封面及已确认高清审片版验收。公开发布仍必须单独获得用户授权。


publish 入口已包含此检查；入口已通过且所有输入输出未变时，不额外重复同一轮完整验收。修正文案、封面或索引等配套产物后必须重新执行独立门禁。

## 六、公开发布与登记

发布包检查通过后，才进入公开发布确认。公开发布是外部操作，必须获得用户明确授权；已获授权不重复询问。不能把“同意发布”当作“发布成功”。用户确认已经成功公开发布后，由 AI 同步台账字段 dashboard_status="已发布"、publish_status="已发布" 和 status="Vn 已公开发布"，在 notes 记录实际平台、成功时间及确认依据，幂等更新。

用户确认已经公开发布后，AI 同步向 `course/published-videos.json` 新增或更新本期条目。目录只记录已发布课程，至少保存 `episode`、`topic`、`recommendation_name`、一段可独立阅读的 `summary`、用于关联判断的 `keywords`，以及制作索引、发布文案和发布视频路径。以 `episode` 为唯一键幂等更新；发布包就绪但尚未公开发布时禁止提前登记。


## 七、冻结与清理

版本冻结后按以下清单清理；先确保长期保留产物存在、路径可追溯，再删除可重建中间物。保留已确认旧版，不能因制作新版本覆盖旧版。

| 长期保留 | 版本冻结后可删除 |
|---|---|
| 原始资料路径与制作索引 | 未选中的风格候选 |
| 定稿讲解稿与整期切分预览 | 每幕临时 `.preview.json` |
| 四幕正式 JSON | 逐句 segment WAV、失败重配目录 |
| 四幕 `actN.wav`、timings 与整期时间表 | `trim/`、concat 清单 |
| 固定风格选择记录与四幕源 HTML | 临时模板副本、无声视频、抽帧目录 |
| 已确认审片版、高清发布版、正式独立封面与发布配套文案 | 未选中的封面候选、已拼入成片的临时分幕视频 |
| `course/episodes.json`、`course/published-videos.json` | 其他可从正式源重建的审片中间物 |

清理 `pipeline/build` 时统一使用项目入口，禁止临时拼接递归删除命令：

```bash
# 默认只预览目标、数量和空间，不删除
node --env-file-if-exists=.env build/common/cleanup_course_builds.mjs --episodes 1-9

# 核对预览后显式执行
node --env-file-if-exists=.env build/common/cleanup_course_builds.mjs --episodes 1-9 --apply
```

脚本只匹配 `pipeline/build` 直属目录下指定期次的 `course_epNN_*` 和 `epNN_*` 产物。存在清理目标时，该期必须在 `course/episodes.json` 标记为“已发布”，制作索引必须存在，且 `publish_output` 必须指向非空正式成片；任一条件不满足则整次操作失败并保持原文件。正式源 HTML、WAV、timings、制作索引、审片版、发布版、正式封面、发布文案、通用开场模板和 `npm-cache` 均不属于该入口的删除范围。重复执行不报错，也不产生额外副作用。
