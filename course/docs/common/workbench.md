# 本地视频工作台

用于查看当前教学与Vibe视频库，以及外层历史课程库的进度、媒体、稿件与分镜，记录带时间点的修改意见，并预览历史版本清理。制作仍由助手按原SOP执行。

## 启动

在 `ai-video-workflow/` 根目录执行：

```bash
npm run workbench
```

浏览器打开 `http://127.0.0.1:3211/`。需要Node.js 22.9以上；读取真实视频时长和保存意见需要已有的FFmpeg／ffprobe环境，不需要安装新的前端依赖。Windows跨WSL直接运行时可使用 `node.exe workbench/server.mjs`。

默认仅监听本机。端口被占用时明确报错；需要改端口可设置环境变量 `WORKBENCH_PORT`。程序路径根据源码位置计算，单独克隆内层仍可独立运行；本机父目录有课程台账时，额外提供历史视频库。

## 使用

1. 在总览按教学／Vibe、主题或状态筛选；每期可选择“制作中／待发布／已发布”并点击保存。状态写入所选视频库台账，刷新或重启后保留。详细制作记录在期次页及“分幕进度”中查看。
   每期右侧的“发布文件夹”会用Windows资源管理器打开当前制作索引中 `publish_output` 对应视频的所在目录，不跟随预览或历史候选。尚未登记发布版或文件不存在时按钮不可用，悬停可查看原因；该操作不会修改文件或生产记录。
2. 选择当前视频、独立分幕或已登记的历史版本。“其他候选”可展示本期输出目录中发现的其他视频；没有可靠范围的候选明确标为“范围未核验”。
3. 播放到需要修改的位置，点击“记录问题”。描述框上方直接显示起点和终点，默认都填当前分秒；相同表示这一秒，只填写描述即可保存。要标记一段，直接把终点改晚。保存后可编辑、改变处理状态或点击时间回放；相同起止回放这一秒，不同起止按区间回放。
4. 意见默认只显示当前文件的未解决项。切到“本期全部版本”可以查找旧意见；旧意见仍绑定原文件，不自动平移到新版。
5. “复制清单”复制勾选项；未勾选时复制当前筛选结果。把清单交给助手开展修改。复制受浏览器限制时，页面提供可手动复制的文字。
6. 下方材料区提供讲解稿、分镜和发布资料。有可靠映射时跟随播放；分镜总索引引用的本期子文档可直接打开。无法确认对应或视频身份、时长不符时显示说明，保留全文。

## 两个视频库

左侧“视频库”选择“当前视频库（内层）”或“历史视频库（外层）”，默认当前库。列表、状态、播放、章节、材料、发布文件夹和意见共用界面；旧库缺失的资料明确显示缺项。每个链接、媒体请求、意见及草稿均区分库；相同期号不会混用。后续制作继续在内层维护。

意见分别保存在所属库根目录的 `.local/video-workbench/<期号>/feedback.json`。当前库已有意见和草稿位置不变，历史库新增记录与当前库分开；复制交接清单包含视频库名称。

## 历史版本清理

1. 在总览点击“历史版本清理”，确认顶部视频库名称，可用“全选已发布期次”或逐项勾选已发布期次，再点击“统计并预览”。全选数量和部分选中状态只计算已发布期次；制作中、待发布及其他未发布期次显示但禁选，不能进入页面清理预览。执行前会再次核查发布状态，预览后改为未发布也不能删除。
2. 预览分别显示检查范围占用、核查通过可清理空间和保留空间。允许核查通过的旧派生MP4，以及人工登记并再次复核通过的旧检查图片、重复字体；其他构建文件计入占用并保留。勾选“显示受保护文件”可查看逐文件理由和依赖核查说明。
   历史记录和确认文字继续保留，不单凭旧路径锁住视频；实际素材、源码、跨期引用及意见绑定仍保护。文档中的命令示例不算生产依赖，正式素材清单继续核查。
3. 展开“保留发布母版”核对留下的文件，沿用现有发布文件名，画面、声音和配乐均不改变。可按“旧视频／相同整片副本（可恢复）／旧检查图片／重复字体”筛选，勾选“全选”或逐项选择；切换类别会清空文件选择。核对数量、预计释放空间和路径后，点击“清理选中文件”并确认，服务端重新扫描发布状态、两库依赖、当前验收、核验登记和文件身份；预览后变化会拒绝执行。
4. 清理只删除选中的准确文件，不删除整个旧版目录。被舍弃的旧版和旧检查图片不承诺恢复，也不移动到回收站；源码、声音、素材原件、确认JSON、当前验收图片、发布母版和内容不同的当前审片继续保留。字体仅删除与保留原字体完全相同的旧构建副本。相同整片副本仅在SHA-256与发布母版一致、没有其他实际输入引用且依赖核查通过时允许归档。清理结果显示实际数量、字节和审计记录位置；部分失败会停止并保留已执行记录。

已核验候选登记位于所属库 `.local/video-workbench/cleanup-reviewed.json`，记录准确路径、摘要及必要的保留来源或历史JSON位置。登记本身不执行删除；新生成或内容改变的图片、字体需要重新核查。登记与源字体变化、当前幕版本冲突、图片被当前输入或两库验收报告复用时，相关文件不可清理。大批清理还保存同目录逐项events.jsonl审计事件，处理中断时保留该文件和审计JSON。

相同副本的原路径、母版路径和摘要分别登记在所属库的 `.local/video-workbench/retained-media.json`，必须随个人制作记录保留。原制作索引、确认路径和确认摘要不改写。副本清理后，版本菜单标明“已归档，读取母版”，文件信息显示实际读取的母版；播放器和意见仍保留原版本归属。点击“恢复整片副本到原路径”会创建独立的相同文件，不覆盖已有其他内容；母版缺失或摘要变化会明确拒绝读取和恢复。

工作台、视觉证据及独立发布检查支持该归档记录，不会因此重造确认。再次制作时需要原路径，先在工作台恢复副本。教学／Vibe路线命令及npm的review、publish:package兼容入口会检查实际输出目标，拒绝覆盖已承担恢复用途的发布母版，新的内容另存版本；已锁定的渲染代码和原审片输入摘要保持不变。底层course_video.mjs直调属于调试入口，不具备这层归档写保护，归档后制作应使用上述npm入口。原发布文件一直保留，因此“发布文件夹”和已发布状态保持可用。

清理计划及审计保存在内层 `.local/video-workbench/cleanup/`，同时记录目标视频库。旧命令的重建式清理入口继续暂停，本功能使用用户明确批准的“核查依赖后舍弃无用旧版”边界，具体要求见同目录 `published_cleanup.md`。

## 保存位置与边界

正式意见保存在 `.local/video-workbench/<期号>/feedback.json`，浏览器关闭或服务重启后仍保留。该目录属于个人创作记录，需要保留或备份，不是可以随意删除的渲染缓存。浏览器存储只辅助恢复尚未提交的草稿。

通用工作台代码、测试和使用说明随Git仓库分发；本机的核验清单、归档映射、清理计划、审计和意见保存在已忽略的 `.local/`，开发核验资料保存在已忽略的 `specs/`，均不提交远程。其他电脑按自己的台账和文件重新扫描；没有本机核验登记时，旧检查图片和重复字体不会自动进入可清理范围。迁移个人制作环境时，应另行备份并迁移归档映射、母版及相关制作记录。

工作台仅在用户保存主页状态时修改所属库 `course/episodes.json` 对应期次的 `dashboard_status` 和 `publish_status`；详细生产记录、审片证据、制作索引、原稿和原媒体均不因此改动。意见单独保存。状态保存不生成视频或执行上传，意见标为“已解决”也不表示整片已确认。旧派生视频的删除仅通过上述历史版本清理入口，在逐项预览和确认后执行。

页面统一采用正文16px、辅助信息14px、最小12px的字号；时间默认显示为“分:秒”，历史意见中已有的毫秒数据仍可读取。

文件路径、指纹和意见保存位置可在播放器下方“文件与版本信息”中查看。当前视频缺失时会报缺项，不会自动把旧文件当成当前版。同路径的视频内容变化后，应重新载入并复核；旧意见仍保留原始归属。
