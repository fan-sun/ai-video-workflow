# 共用输出路径与历史兼容

正式制作使用所选路线 SOP 的 init、review、publish 和 check-release 命令。路线入口在调用共用工具前核对索引 route；命令与索引不符时立即报错，不更改路线或启动渲染。既有 review、publish:package 和底层 Node 入口保留兼容，新的制作说明优先使用路线命令。

## 新期次的目录规则

各路线 SOP 声明自己的默认输出根目录。根目录之下统一为 `epNN_slug/vK/`，以期次和内容标识隔离视频，以版本目录保留已确认结果。审片底片、混音审片、正式发布视频、同版本发布文案及发布目录内封面归属同一期次与版本；具体生成时机由路线规定。

共同路径由 `build/common/output_paths.mjs` 计算，不能在示例、文案脚本或发布步骤再写一套固定根目录。新期次初始输出字段仍为 null，实际文件生成并通过检查后才登记，初始化不把计划位置伪装成已生成文件。

临时构建仍使用 `pipeline/build/`，正式源码和本期索引仍按[登记文档](topic_selection.md)保存；输出分流不改变这些输入位置或期号。

## 已有期次

已有索引登记在 `pipeline/output/course/` 下的期次，继续在该历史根目录按当前版本计算输出，避免重跑时自动迁移视频及确认记录。已有明确输出路径按既有工具契约复用；新建期次没有历史登记时使用路线默认根目录。不要为了进入新目录清空索引、改写确认事实或重复初始化已有期号。

路线专属目录与索引路线明显不符时，计划生成阶段拒绝。需要迁移已有期次时应作为独立迁移处理，核对真实文件、脚本依赖、索引、台账、发布记录及哈希确认；不能仅移动文件夹。本规则不执行历史迁移。

## 发布与复查

Vibe 的混音基于实际底片路径另存，因此跟随该期输出目录；发布封面跟随正式发布文件所在目录。同版本文案必须与发布文件位于同一版本目录。实际文件登记、媒体检查及发布包一致性按[共用发布交付](release_delivery.md)执行。

清理候选扫描兼容路线新目录与历史目录，仍只读取已发布期次的实际登记路径；删除暂停和独立重建限制按[共用清理规范](published_cleanup.md)，分目录不构成删除授权。
