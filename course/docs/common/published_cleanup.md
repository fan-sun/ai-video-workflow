# 已发布视频的共同保留与清理规则

以目标版本完整重建依赖判断保留范围，不按名称、版本新旧或已发布状态直接删除。未发布期次暂不清理。旧通用命令的自动删除仍暂停，非空 --apply 会拒绝。工作台另按用户明确批准的“舍弃无依赖历史版本”边界提供逐文件手动清理，要求见下文；不能用该入口递归删除旧目录。

本文的“同一个视频”指同版画面、声音、字幕、顺序和时间保持一致；重新编码后的 MP4 不要求文件哈希相同。若要求逐字节完全相同，直接保留原 MP4。

## 一、先确定重建的起点

每期固定一个目标发布版本，从它反向查找全部输入，包括源文件引用的素材、脚本导入的其他脚本、音频、字体和配置。输入也可能由上游生成：例如 AI 配音、AI 图片已经选定后，应作为本版冻结输入保留，不能只留提示词后重新生成来冒充恢复原版。

| 文件与目标版本的关系 | 处理方式 |
|---|---|
| 重建需要读取，且无法从其他保留文件稳定恢复 | 必须保留 |
| 有保留的输入、完整生成步骤，且已独立重建并对照通过 | 才能进入逐文件待删清单 |
| 不属于目标版本，看起来也未被引用 | 仍需排除其他期次、素材库、辅助脚本和保留入口的依赖；未核实前保留。经核查后可进入工作台手动舍弃历史版本清单 |
| 尚不清楚来源、引用关系或生成方式 | 先保留，不能仅凭文件名判断 |

“只保留最新版本号”不成立：最新整片可能复用了多个旧版本的声音、画面或脚本。保留的是目标版本的完整依赖，而不是所有历史版本，也不是单独一个最新文件夹。

## 四、最终成片与历史版本是否必须留

每期保留现有发布文件作为母版，沿用发布文件名及原画面、声音、配乐，不自动增删音乐。当前没有全部期次独立重建证据，发布原片及配套封面、文案继续保留。内容不同的当前审片版同样保留，不能仅因分辨率相同或文件较大就删除。

当前整片审片副本若与发布母版SHA-256完全一致，可以采用更严格的逐字节复制恢复证明，无需重新渲染画面。核查其他期次、跨库、素材和辅助入口的实际输入后，由工作台先登记原路径、母版路径、大小及摘要，再删除准确副本；实际源码引用或依赖不明者继续保护。归档记录保存在所属库 `.local/video-workbench/retained-media.json`，不能当作缓存删除；原确认记录及其路径、摘要不改写。

读取明确归档且缺失的副本时，工作台和内层验收检查仅在母版摘要一致时读取母版，并保留原版本身份。恢复原路径需要复制出独立文件并校验，不使用与母版共享内容的硬链接。再次制作需先恢复副本，教学／Vibe路线命令及npm兼容入口按引擎实际输出规则阻止覆盖保留母版，新改动另存版本；不改动已锁定的渲染代码或原确认摘要。底层渲染脚本的调试直调不提供这层写保护。此例外只适用于完全相同的整片副本，不放行内容不同的审片、素材或任意历史视频。

旧音轨、源码和素材继续保留。旧审片与旧导出仅在完成两库、跨期、素材库、辅助脚本和保留入口核查后，才可作为手动舍弃候选；只检查当前索引不够。保留人工选择、确认、验收 JSON 和原片哈希记录；重跑程序不能重造原来的确认事实。

## 工作台手动舍弃历史版本

用户已明确选择：保留目标发布版及完整依赖，允许放弃不再使用的历史派生视频，不要求重新生成被放弃的旧版本。该操作与“相同整片副本可从发布母版恢复”分开显示，不把舍弃旧版描述为可恢复缓存。

入口为本机工作台的“历史版本清理”，可选择当前内层库或外层历史课程库。处理已发布期次输出目录与正式构建命名下的旧派生MP4；另可登记经人工核验的旧检查图片与重复构建字体。未登记的非MP4、未知构建视频、素材原件、音频、源码、配置与记录保留。目标发布文件缺失、台账与索引不一致、链接越界或实际依赖不明时不能执行。

人工核验登记保存在所属库 `.local/video-workbench/cleanup-reviewed.json`，不依赖开发归档目录。旧检查图片仅限准确登记的PNG/JPG路径和内容摘要，所属幕必须早于当前实际使用版本；源码和审片版本冲突时保留。当前输入、两库当前验收报告、辅助代码或动态输入涉及的图片继续保护，旧JSON和确认文字不删。重复字体仅限准确登记的旧构建副本，核对保留源字体及副本SHA-256一致；源字体和当前构建继续保留。新增文件、内容变化或未知目录不会自动获得删除资格。被放弃的旧检查图片按舍弃旧版处理，不承诺恢复。

登记也可注明已逐项核实的历史JSON位置及原视频值；只有对应索引、位置和值同时匹配才将其视为历史事实，不能覆盖正式输入、当前审片或发布输出。同一视频的其他实际引用继续保护。已核实的通用工具输出常量仅在对应工具源码SHA-256保持一致时采用，工具变化后例外失效；不能笼统忽略缺失JSON输入。

清理计划必须逐文件列出库、期次、路径、大小及保护原因。当前索引和实际源文件、跨库跨期引用、素材索引、辅助输入及意见绑定的视频均需核查；通用工具可以接收任意输入参数，不等于所有历史文件都是实际依赖。保留源中的动态视频输入不能明确归属时，相关范围继续保护。

制作索引中的历史基线、旧版审片记录及明确确认事实继续保留，但其中的视频路径不单独构成运行依赖；同一视频被实际源码、其他期次或素材清单读取时仍保护。链接到的版本制作索引沿用同一解释规则，不把旧验收报告重新当作生产入口。素材数据里的history、records或recordings集合不因此变成历史事实，实际输入继续展开核查。

Markdown说明文档的代码块、行内代码和引号命令示例不作生产输入；正文中的现存媒体链接或video/source嵌入仍保护，缺失说明链接只提示，不封闭整期。正式CSV/TXT素材清单继续识别明确的视频值，不能套用说明文档的示例排除规则。

用户在页面选择准确文件并确认后，执行前重新检查文件身份和依赖状态，包括核验登记、当前验收和保留源字体。只能逐文件删除服务端计划内的允许项，不能由客户端传入任意路径，不能递归清空版本目录。审计在删除前落盘并逐项更新；超过100项时将逐项事件追加到同目录events.jsonl，成功或失败后保存完整审计快照，避免每删一个文件重写整批清单。处理中断时连同事件记录核对实际文件。重复执行同一选择不重复删除，失败记录实际已删除数量并停止。旧命令的非空apply继续拒绝，不增加强制绕过参数。

## 独立重建验证

1. 固定目标版本，列出重建起点、全部输入及其依赖、工具版本和执行顺序；同时排查其他期次、Python/MJS/JSON、动态路径、核对脚本和只复用缓存的入口。
2. 复制保留输入到独立工作目录，用隔离环境确保程序不能读取原工作区、绝对路径或其他缓存来补齐候选；不覆盖已发布原件。
3. 对视频候选，从画面源实际重新渲染、合音、拼接和混音，生成完整视频。对拼接 WAV 等单个中间物，可以用更严格的逐字节恢复证明：原件移出生成路径，在全新目录中仅使用保留输入重建，SHA-256 必须与原件相同。这个证明只适用于该文件，不能推广为整条视频路线已经验证。
4. 对照原片核对画面、文字、声音、时长和幕间接续，再确认其他保留入口及期次不依赖候选。一次运行没有读取某文件，并不能单独证明它可以删。
5. 清单落实到准确文件路径，记录输入、生成步骤和验证结果；继续保留原片与确认记录。无法完成上述核对的文件不删。


文件存在、哈希未变化、源码检查通过或单个中间物可恢复，均不能证明整条路线独立可重建。按所属路线的重建输入清单核对，保存原件和确认事实；重新调用模型不能恢复同一份已确认音频或图像。

## 仅预览候选

```bash
node build/common/cleanup_course_builds.mjs --published --intermediates
```

--episodes 1,2 可限定期数，显式指定未发布期次会拒绝；省略 --intermediates 仅列出 build 候选。扫描只识别部分引用，可能漏掉脚本导入、动态路径、跨期和辅助入口，输出不是获准删除清单。applyCourseBuildCleanup 对非空计划统一报错，没有强制绕过参数；不得另写递归删除命令绕过。

状态在视频看板选择“新视频库（教学 / Vibe）”管理；状态只决定是否进入核对，逐文件依赖和重建证据决定能否删。个别历史验证和专用恢复执行器不构成新一期的删除授权。

本文件不依赖本机 specs、外层仓库或历史清理批次。所属路线 SOP 提供其重建输入入口；实际处理结果留在本地过程归档，不继续写入生产规范。

## 共同重建输入与待核对候选

必须保留目标版本索引、正式文稿、正式时间信息、画面 HTML/JS/CSS、全部引用素材和字体、生成脚本及辅助模块、工具版本与配置、正式封面、混音参数，以及发布母版、内容不同的当前审片和确认/验收记录。相同审片副本仅适用上文已登记的归档例外。各路线补充自身的音频和时间文件及工具实际依赖，不重复维护本清单。

可能可重建的候选包括构建副本、无声及临时分幕视频、拼接底片、字幕派生文件、拼接清单、预览截图、接触表和纯运行日志。它们必须逐文件排查全部期次、脚本、跨版本和增量入口，完成前述独立重建验证才能讨论删除；JSON 验收记录不随目录整批删除。旧片、背景试做或候选方案也不能按名称整目录清理。

抽帧 PNG 后来若作为背景或过渡素材使用，它已成为重建输入；生成过的声音或图像也不天然是缓存。不能只保留提示词、歌曲名、下载链接或随机种子，便认为能恢复同一个已确认素材。独有的人工修改必须保留。
