# 已发布视频：按重建依赖清理中间产物

目标：视频发布后，只保留重新生成该版本所需的输入和生成方法，删除能够从这些输入重新得到的中间产物。

**判断文件能否删除，看它是否能从保留的输入重新生成。已发布只是开始清理的时机，不代表该视频目录中的文件都可以删除。** 未发布期次暂不清理。

**安全复核结论（2026-10-17）：已验证并删除《沉没成本》的七份整片拼接 WAV（91,133,108 字节，见第九节），以及 AI 教学第 01 期的三份配乐试听对比 MP4（517,402,085 字节，见第十节）。这些文件均从保留输入逐字节重建通过。** 《沉没成本》第一幕 MP4 重渲未通过像素完全一致的保守门槛，已恢复原件；没有据此扩大删除其他视频。其他候选默认保留，尤其不能把逐句原始配音、旧版本目录、审片视频和验收记录直接当作可删项。通用自动删除入口仍暂停。

本文的“同一个视频”指同版画面、声音、字幕、顺序和时间保持一致；重新编码后的 MP4 不要求文件哈希相同。若要求逐字节完全相同，直接保留原 MP4。

## 一、先确定重建的起点

每期固定一个目标发布版本，从它反向查找全部输入，包括源文件引用的素材、脚本导入的其他脚本、音频、字体和配置。输入也可能由上游生成：例如 AI 配音、AI 图片已经选定后，应作为本版冻结输入保留，不能只留提示词后重新生成来冒充恢复原版。

| 文件与目标版本的关系 | 处理方式 |
|---|---|
| 重建需要读取，且无法从其他保留文件稳定恢复 | 必须保留 |
| 有保留的输入、完整生成步骤，且已独立重建并对照通过 | 才能进入逐文件待删清单 |
| 不属于目标版本，看起来也未被引用 | 仍需排除其他期次、辅助脚本、增量入口和历史版本的依赖；未核实前保留 |
| 尚不清楚来源、引用关系或生成方式 | 先保留，不能仅凭文件名判断 |

“只保留最新版本号”不成立：最新整片可能复用了多个旧版本的声音、画面或脚本。保留的是目标版本的完整依赖，而不是所有历史版本，也不是单独一个最新文件夹。

## 二、AI 教学线路

重建链路：

```text
同版分幕画面源 + 引用素材/字体 + 正式音轨 + 字幕时间信息 + 章节/封面配置
  → 生成构建副本与字幕
  → 渲染各幕无声视频
  → 合入各幕声音
  → 拼接、加入封面及发布音频
  → 最终发布视频
```

| 必须保留的重建输入 | 对应内容 |
|---|---|
| 目标版本的制作索引和配置 | 分幕顺序、时长、章节、封面、输出规格及输入路径 |
| 定稿与正式分幕 JSON | 保留准确文字、切分和字幕内容 |
| 各幕最终 WAV 与对应 timings | 复用已确认的同一段旁白及时间轴，不重新调用配音模型 |
| 尚存的逐句原始 WAV、裁切素材与配音处理记录 | 原始音频不能从裁切、变速后的最终 WAV 无损恢复，当前保留，不列入获准删除范围 |
| 各幕实际使用的 HTML/JS/CSS | 保留已经完成的画面编排和动画 |
| 源码实际引用的素材、字体、模板和辅助代码 | 包括插入的视频、图片，以及从其他版本复用的文件 |
| 正式封面原图、整期时间表、混音参数及工具版本 | 恢复同版外观、章节时间、声音和编码规格 |
| 审片 MP4、已发布 MP4、人工确认及验收记录 | 现有发布步骤依赖审片音频；保留原件和验收依据，供重建对照 |

以下只是可能可重建的候选，除第十节已验证的三份配乐试听对比 MP4 外均保留；每项必须通过第六节验证后才能删：

| 待核对候选 | 必须验证的条件 |
|---|---|
| 自动生成的 SRT、字幕注入后的构建 HTML、模板工作副本 | 正式 JSON、timings、画面源和工具可重建，且候选没有独有人工修改 |
| 各幕无声 MP4、临时分幕 MP4、整期无声底片 | 必须从保留输入实际重建；不能破坏只复用缓存的换封面、衔接预览等入口 |
| 临时拼接视频、试听文件、拼接 TXT | 核对准确版本、输入顺序及生成步骤，排除仍作为音频/视频输入的文件 |
| 检查截图、抽帧、接触表和纯运行日志 | 保留产生它们的同版输入；排除素材引用和验收依赖。JSON 验收记录不随目录整批删除 |
| 失败试做、局部预览和旧版本 | 对所有期次及辅助入口排除引用；不能按“旧”“preview”或版本号整目录删除 |

原始逐句 WAV 可能含被裁掉的声音，最终 WAV 还可能经过变速、拼接和压缩。二者不能互相无损恢复。仅在明确只需从最终 WAV 重建整片、且整条路径已验证时，才有讨论放弃逐句编辑素材的前提；这仍属于放弃原始素材，不能称作删除可重建缓存。本规则当前保留尚存的这类文件。

**当前入口的额外依赖：** `build/common/course_video.mjs` 的教学 publish 步骤从 `review_output` 审片 MP4 复制音频。因此现有命令链还依赖这份审片 MP4，不能只因为它叫“审片版”就删除。若要删除，必须先验证可从保留的音轨重建所需审片输入，或提供不依赖该 MP4 的发布音频输入。不能把“各幕 WAV 都在”直接当作现有 publish 命令已能原样恢复的证明。

## 三、Vibe 线路

重建链路：

```text
同版 HTML/JS/CSS + 引用素材/字体 + 画面时间表
  → 渲染各幕无声视频
  + 动作音效及其时间安排
  → 各幕带声音视频、整期未加背景音乐底片
  + 原始背景音乐及混音参数
  → 完整混音视频
  → 发布视频
```

| 必须保留的重建输入 | 对应内容 |
|---|---|
| 同版画面源与其全部引用素材 | 实际采用的 HTML/JS/CSS、图片、视频、字体等 |
| 正式文稿、逐屏文字、画面时间表与制作索引 | 每屏文字、出现时间、幕间关系和总时长 |
| 已确认动作音效文件及其时间安排 | 保留实际声音；只存在生成脚本或固定随机种子不足以证明输出与原声一致，当前不删除这些 WAV |
| 原始背景音乐 | 保留实际使用的音乐文件，不能只保留歌曲名或下载链接 |
| 混音参数 | 动作声音量、音乐音量、起点、循环、裁切、淡入淡出、声道和总时长 |
| 生成脚本、辅助模块、依赖版本和必要配置 | 保留能重跑的实际方法；有随机过程时还须固定随机参数 |
| 未混背景音乐的底片、完整审片版、发布版及确认记录 | mix/publish 仍读取这些 MP4，publish 还校验已确认审片版的哈希 |

以下只是可能可重建的候选，除第九节已逐文件验证的七份 WAV 外均保留；每项必须通过第六节验证后才能删：

| 待核对候选 | 必须验证的条件 |
|---|---|
| 预览截图、逐帧 PNG/JPG、检查接触表 | 能从保留的同版输入重新生成，且未被作为背景、过渡图或验收依据引用 |
| 各幕无声 MP4、临时分幕 MP4、整期拼接底片 | 验证完整渲染、合音和拼接链，排除任何直接读取旧片的步骤 |
| 音乐循环版、裁切版、试混音和中间混音 WAV | 必须保留原音乐及精确循环、裁切、增益、淡入淡出参数；索引实际引用的音乐文件先保留 |
| 构建副本、渲染缓存、拼接 TXT、纯检查日志 | 逐文件确认生成来源与引用；目录中独有源码、素材及 JSON 记录不随目录删除 |
| 背景试做、动作试做、旧片和候选方案 | 对全部期次和跨版本生成/核对脚本排除依赖后，才判断是否已废弃 |

**不能只看文件来源：** 一张从视频抽出的 PNG，如果后来被 HTML 当作下一幕的背景使用，它现在就是重建输入；只有保存并验证了它的生成链路，才可以删后重建。同理，生成过的声音或图片不一定仍属于可直接删除的中间物。

**当前入口的额外依赖：** Vibe 的 mix 入口读取未混背景音乐的底片；publish 入口复制已确认的审片视频，不负责从 HTML 重新渲染。要删这些 MP4，必须能先从源文件重建各幕、拼接底片并重新混音。仅保留 publish 命令不能恢复被删掉的底片。

Vibe publish 还要求审片文件与 `review_approval.sha256` 一致。重新编码即使观感相同，哈希也可能不同；不能仅为通过检查而改写人工确认记录。因此当前审片原件和确认记录一并保留。

## 四、最终成片与历史版本是否必须留

最终 MP4 在生成关系上属于派生物，但当前没有完整独立重建证据，且还承担回退、比对和发布验收作用。本规则保留已发布原片、已确认审片版及配套封面、文案，不列入自动删除范围。

旧审片、旧成片和旧音轨默认保留。只检查当前索引不足以证明旧版无用，还需排查其他期次、辅助脚本、历史哈希核对及增量入口。保留人工选择、确认、验收 JSON 和原片哈希记录；重跑程序不能重造原来的确认事实。

## 六、什么才算验证了“删后能恢复”

1. 固定目标版本，列出重建起点、全部输入及其依赖、工具版本和执行顺序；同时排查其他期次、Python/MJS/JSON、动态路径、核对脚本和只复用缓存的入口。
2. 复制保留输入到独立工作目录，用隔离环境确保程序不能读取原工作区、绝对路径或其他缓存来补齐候选；不覆盖已发布原件。
3. 对视频候选，从画面源实际重新渲染、合音、拼接和混音，生成完整视频。对拼接 WAV 等单个中间物，可以用更严格的逐字节恢复证明：原件移出生成路径，在全新目录中仅使用保留输入重建，SHA-256 必须与原件相同。这个证明只适用于该文件，不能推广为整条视频路线已经验证。
4. 对照原片核对画面、文字、声音、时长和幕间接续，再确认其他保留入口及期次不依赖候选。一次运行没有读取某文件，并不能单独证明它可以删。
5. 清单落实到准确文件路径，记录输入、生成步骤和验证结果；继续保留原片与确认记录。无法完成上述核对的文件不删。

文件仍存在、哈希未变化、源码检查通过，均不能代替完整重建验证。本次此前清理验证了保留文件内容一致，尚未进行上述两条线路的完整独立重建，不能据此扩大为“所有派生物现在都能删”。

## 七、现有工具只做候选预览

在 `ai-video-workflow` 下，以下命令预览目前脚本支持的已发布期次中间物：

```bash
node build/common/cleanup_course_builds.mjs --published --intermediates
```

现有候选扫描仍会按 build 前缀、抽帧目录、silent 文件名、raw/trim 和 concat 名称列出文件。它只识别部分引用，不是完整依赖分析器；**预览中的每一项，包括仍被列出的原始 WAV，都不代表已获准删除。** 源码检查会漏掉 MJS/Python/JSON、动态拼接、跨期使用，以及未覆盖的 Vibe 字段。

为执行“宁可少删，不能多删”，`applyCourseBuildCleanup` 对非空计划统一报错并保持文件原样，CLI 的 `--apply` 和旧归档执行器都不能绕过。没有新增强制删除参数。《沉没成本》的专用验证执行器只允许第九节七个精确 WAV 路径；教学线专用执行器只允许第十节三个配乐对比 MP4 路径。两者均在删除前核对候选、重建结果及保留输入哈希，不接受按目录或文件类型扩大范围。不能把缺少引用记录当作删除证据。

发布状态仍在原入口 <http://127.0.0.1:3210/> 管理，选择“新视频库（教学 / Vibe）”。状态只决定是否进入清理流程，文件清单由重建依赖决定。

## 八、此前清理的实际影响与本次核查边界

此前清理记录包含 505 个逐句原始 WAV 和 416 个裁切 WAV。正式分幕 WAV 与 timings 仍在，但原始逐句文件不能从最终音轨无损还原。此前将这些统称为“可重建中间物”不准确；本次没有尝试重新配音来冒充恢复原文件。

第 01 期的 `v21/publish_ai_cover.mjs` 强制复用第 2—6 幕高清缓存；这些 build 目录已被清理，该“只换封面”入口目前不能直接重跑。`v21/make_join_preview.mjs` 也直接读取已删除的第六幕缓存。它们需要先重建缓存，不能因为正式源仍在就宣称全部旧命令均可原样重跑。

上轮只读核查确认：第 01 期当前完整发布计划列出的直接输入仍存在；第 02 期当前分幕画面源、时间表、动作音效、分幕成片、配乐和已核查的跨版本直接输入仍存在。两期索引直接列出的 91 个输入及正式文件均存在，其中 90 个与此前保留记录的 SHA-256 一致；剩余背景音乐位于 specs，没有列入旧哈希记录，当轮确认其文件存在。第 02 期已追踪的渲染/抽帧步骤会先生成其 silent 视频和截图再读取。这是文件存在性与代码依赖核查，没有证明所有动态路径均无缺失。随后用户授权的实际试删结果见下节。

也可在末尾指定版本，例如 `full-background-v2`。恢复器固定核对历史原件哈希，源音效改变时会报错；现有目标内容不同时不会覆盖。各原版 assemble 脚本本来就会先拼接生成这些 WAV，再读取它们；单独恢复命令可避免为了恢复 WAV 而重写视频或验收记录。

### 未删除：分幕视频及其他候选

第一幕使用保留的背景 v2 源码、字体、动作音效和现有 HyperFrames 0.6.113 实际重渲；浏览器 GPU 与 NVENC 均已确认。结果为 1920×1080、30 fps、28 秒、840 帧，完整解码通过，解码声音与原片一致；解码画面不完全一致，首次对照的全片 SSIM 为 0.998959，复测仍未达到逐帧一致。

这不等于视频无法播放或有明显错误，也不能据此断言已完整复现。差异原因尚未确定，该轮按“可以少删，不能多删”保留原 MP4，未继续扩大到其他幕或整片底片。该轮 AI 教学线路未新增删除，后续教学专项清理见第十节。第 03、04 期未发布文件不处理。两条线路从画面源开始的完整独立重建仍未完成。

本地过程证据位于 `specs/发布后清理验证/验证结果.json`，包括候选、原件哈希、保留输入哈希、恢复验证和删除结果。`trial.py` 的 `audio` 用于暂移并验证尚存在的七份 WAV，`restore` 用于异常退出后的原件恢复，`finalize` 只接受这七个路径的逐字节通过记录。需要重复清理时，先运行上述恢复命令，再依次运行 `python -X utf8 specs/发布后清理验证/trial.py audio` 和 `python -X utf8 specs/发布后清理验证/trial.py finalize`。试验产生的大体积临时副本在完成后清走，保留小体积记录和日志。
