# 共用执行、确认与版本规则

适用于主 SOP 选择的各路线。路线 SOP 决定阶段顺序及专属用户门禁，本文只维护共同执行边界。

## 开始与恢复

先读主 SOP、course/episodes.json 和本期制作索引，依据真实文件及已有确认定位当前阶段。进入阶段时读取对应子文档，不要求开工一次读完全部文档。SOP 是已批准流程，不另造需求、设计审批；所属路线要求的本期编排和验收产物仍须生成。

主题类型与表达路线分别选择；用户已指定的路线和主题直接沿用。已有确认在内容未改变时继续有效。历史案例不能覆盖现行规则。

## 执行与记录

- 路线列出的门禁之外，正常生成、技术检查及可修复问题由助手连续完成。缺少必要参数、规则冲突或无法修复时说明具体问题；不吞异常或静默降级。
- 长任务结束后独立核对产物，不以进度条或退出码代替完整验收。尚未生成的路径填 null，生成并检查后才登记；不伪造确认、检查或完成事实。
- 正式源码与临时构建分开，修改只影响需要返工的范围；局部预览不是整幕完成，局部认可不能扩成整片认可。
- 技术示例仅验证链路，不创建用户试听、审片或公开发布事实。
- 工具运行、自动技术检查、助手视觉判断、用户确认分别记录；只有实际完成的项才能写通过。阶段入口要说明输入、动作、可检查产物与通过条件。

## 版本与修改

保留已确认版本，修改另用新版本文件名，不能覆盖旧文件后沿用旧验收。未变化且仍有效的素材和确认可复用；改变已确认内容时回到所属路线对应阶段。源码、素材或时长变化后复核受影响构建、字幕、接点、整期时间及发布配套文件，不手改通过状态。

本期脚本和文件位置按[选题与登记](topic_selection.md)，实际渲染及缓存按[渲染验收](render_verification.md)，发布状态与授权按[发布交付](release_delivery.md)，保留和删除按[清理规则](published_cleanup.md)。

## 规范维护

共同规则只在 common 维护，各路线在执行阶段链接；专属规则只在所属路线维护。入口可说明何时读取与执行，不能再复制一套详细规则。迁移时同步引用与锚点，并检查阶段入口和验收路径没有丢失；链接存在不等于执行行为等价。
