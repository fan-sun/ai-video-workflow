# 共用旁白语义切分预览

教学与 Vibe 都在正文审查通过后、既有内容与切分确认前执行本步骤，即使本期不生成旁白音频也要执行。这里生成原文语义句组供审阅，不决定逐屏字幕、动画场景或成片时长；是否配音及后续步骤由所属路线决定。

## 从正式稿逐幕生成

正式稿使用连续编号的 `## 第一幕`、`## 第二幕`等章节，章节内用顶格、单行的`旁白：...`保存正文。运行前核对正式稿路径、实际幕数和顺序与制作索引一致。独立开场的处理遵循所属路线，不自行添加开场或凑足四幕。

必须实际运行[现有切分程序](../../../build/teaching/course_act_split_preview.mjs)，不能以手工分段或逐屏字幕文件代替。程序虽位于`build/teaching/`，本步骤只复用它的文本预演，不调用声音克隆、FFmpeg或渲染。

先查看单幕输出，以下路径替换为当前期次：

```bash
node --env-file-if-exists=.env build/teaching/course_act_split_preview.mjs \
  --md course/scripts/03-topic-slug.md \
  --act 1 \
  --format table
```

再逐幕保存程序结果；初始化已创建本期`pipeline/01_script/NN-slug/`目录：

```bash
node --env-file-if-exists=.env build/teaching/course_act_split_preview.mjs \
  --md course/scripts/03-topic-slug.md \
  --act 1 \
  --format both \
  --out pipeline/01_script/03-topic-slug/course_ep03_act1.preview.json
```

按实际幕数重复，分别替换`--act`和输出文件中的幕编号。保留命令、退出码、各幕段数及 errors/warnings 摘要到已有制作记录；只写“已生成”或填写`generated_by`不构成执行依据。出现解析或校验错误、空幕、幕数不符时先修复，不继续汇总或交付；warnings须逐条判断并记录处理结果。

## 汇总与交付核对

按幕读取临时 JSON 的`segments[].text`，保持顺序、文本、标点和切分边界，汇总到本期`course/episodes/NN-slug/旁白切分预览.json`。整期预览只保存`{"act1":["原文句组"],"act2":["原文句组"]}`这样的纯文本数组，不复制临时文件的`voice`、`voice_id`、停顿等技术字段，也不据此登记已生成音频。

交付前核对以下三项，不能只检查文件存在或拼回正文没有缺字：

- 每幕数组与本轮程序输出的`segments[].text`逐条一致，幕数和顺序与正式稿、索引一致；检查是否拆坏术语、固定表达或悬空指代。
- 每幕拼接后完整覆盖正式稿，保留原文及标点。需要改变断点时回到源稿或程序参数重新生成并复核，不手改临时 preview 后冒充程序结果；涉及正文改词或增删时按原有改稿确认要求执行。
- 索引的`script`、`split_preview`指向本轮真实文件。同一条交付消息给出讲解稿、整期旁白语义预览路径和审查摘要，明确预览类型；其他交付内容及确认范围按所属路线，不另加审批。

语义边界明显不合适、缺少程序结果、汇总与逐幕输出不一致，或交付错了文件类型时，必须退回生成与复核，补交正确文件后才能进入后续步骤。正文覆盖检查通过不代表切分边界合适，也不代表用户已确认。

## 改稿与已有文件

讲解稿或某幕旁白修改后，重新运行受影响幕并汇总整期预览。工具默认拒绝覆盖已有临时文件；需要覆盖时，先确认目标确为本期`pipeline/01_script/NN-slug/`内可重建的临时 preview，再给原命令加`--force`。不得把该参数用于正式 JSON、其他期次或未核对的路径，不沿用旧预览省略重新生成。

重新生成本身不创建或扩大用户确认；内容与切分版本是否仍在原确认范围内，以及绑定如何更新，由所属路线处理。临时 preview 禁止直接传给正式配音工具。
