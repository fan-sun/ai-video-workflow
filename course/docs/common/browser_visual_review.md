# 通用浏览器视觉评审与 HTML 回退指南


> 本文是跨项目通用流程。它适用于界面、海报、视频风格帧等需要比较多个 HTML 视觉候选的任务，不依赖本仓库的画幅、品牌或目录结构。

> 适用范围：本文的 HTML 回退适用于通用静态候选展示。课程制作按 [固定视频风格流程](../teaching/style_preview_workflow.md) 直接复用三张永久预设图，不按期生成风格候选视频；正式封面按 [封面流程](../teaching/cover_workflow.md) 执行强制真实渲染。展示浏览器可选不等于封面和正式视频的渲染验收可选。

## 一、核心原则

1. **候选 HTML 是正式交付物，浏览器只是展示渠道。**
2. 先把每个候选写成可独立打开的文件，再生成本地对比 HTML 并直接交付。
3. 不为展示候选默认启动浏览器；浏览器只用于 AI 按需检查真实渲染、溢出或交互问题。
4. 对比页面是候选文件的展示副本，不得成为唯一保存位置。
5. 不因为浏览器连接失败而改用未经用户授权的其他浏览器、远程服务或截图平台。

三层职责如下：

| 层 | 作用 | 是否必需 |
|---|---|---|
| 候选 HTML | 保存每个真实视觉方案，可独立打开和长期追溯 | 必需 |
| 对比 HTML | 把多个候选并排展示，供用户本地直接打开 | 多候选任务必需 |
| 浏览器 | 打开对比页、记录点击或辅助视觉检查 | 可选 |

## 二、决策流程

```text
生成 2～4 个独立候选 HTML
  ↓
验证文件存在、UTF-8、资源路径和核心内容
  ↓
生成只引用本地候选的对比 HTML → 直接提供文件链接
  ↓
AI 是否需要检查真实渲染、溢出或交互？
  ├─ 是 → 按需启动可控浏览器并执行检查
  └─ 否 → 不启动浏览器
  ↓
用户通过点击或文字回复确认方案
  ↓
把选择结果写回业务索引；浏览器状态不进入业务数据
```

## 三、候选 HTML 的最低契约

每个候选必须：

- 使用 `<meta charset="utf-8">`；
- 有明确的 `<title>`；
- 直接打开即可看到完整方案，不依赖对比页注入内容；
- 使用相对资源路径，或把必要资源一并放入可访问目录；
- 使用真实主题文案与真实构图，不用空白占位框代替关键内容；
- 与其他候选在构图、材质、信息层级或表现隐喻上有实质差异；
- 不要求浏览器插件、登录态或外部接口才能显示基本内容。

若候选只是静态风格帧，不必为了形式完整而增加时间轴、动画或视频工程配置。

## 四、需要自动质检且浏览器可用时

1. 先确认浏览器运行时确实返回可用实例，再启动展示步骤。
2. 本地视觉辅助服务启动后，保存它返回的：
   - 实际 URL；
   - 内容目录；
   - 状态目录。
3. 服务命令可能以前台常驻方式运行，不会立即退出。此时不要重复启动第二个服务，应从状态目录中的 `server-info` 读取端口和路径。
4. 每次展示写入新的语义化文件名，例如：

```text
visual-style.html
visual-style-v2.html
layout-comparison.html
```

5. 对比页已在浏览器启动前生成；浏览器只加载该文件进行真实渲染、溢出或交互检查。
6. 用户在终端中的文字回复是主反馈；浏览器点击事件只作为结构化补充。

浏览器展示前仍需保留独立候选文件。不能只在对比页里画三个缩略图，然后声称已经生成三个候选。

## 五、常见失败信号与处理

| 失败信号 | 含义 | 处理 |
|---|---|---|
| `No browser is available` | 当前没有可控浏览器实例 | 停止浏览器自动化，直接交付候选 HTML |
| 浏览器列表为空 `[]` | 内嵌浏览器或扩展未连接 | 不反复初始化，不切换未经授权的浏览器 |
| 服务命令长期不返回 | 服务可能以前台常驻 | 读取 `server-info`，不要重复启动 |
| `server-info` 存在但 URL 无法访问 | 服务已退出、端口不可达或环境隔离 | 放弃 URL 交付，直接提供 HTML 文件 |
| 页面仍显示旧方案 | 展示服务按最新文件或修改时间选页 | 使用新文件名，不覆盖旧页面 |
| 页面能开但字体、图片缺失 | 对比页无法访问候选的相对资源 | 修正资源路径；独立候选仍应可直接打开 |
| 点击事件没有记录 | 辅助脚本未注入或用户未点击 | 让用户直接回复 A、B、C，不阻塞流程 |

### Windows 与多层 Shell 注意事项

在 Windows 自动化环境中，即使最终调用 Git Bash，外层命令仍可能提前解释 `$()`、竖线和嵌套引号。浏览器服务和状态检查命令应拆成短命令执行；不要把启动、查找、解析 JSON 和页面验证塞进一个复杂字符串。

## 六、浏览器不可用时的标准回退

浏览器不可用时，不再尝试“修好浏览器后才能继续”。标准交付保持不变：

1. 保留所有独立候选 HTML；
2. 验证每个文件存在且非空；
3. 向用户提供对比 HTML 和各候选的可点击本地文件链接；
4. 用一句话说明每个候选的主要差异和推荐方案；
5. 让用户回复 A、B、C 或文件名；
6. 收到选择后继续业务流程。

示例交付格式：

```markdown
- [A · 实体隐喻](<本地绝对路径>)
- [B · 机制流程](<本地绝对路径>)
- [C · 行动教具](<本地绝对路径>)

推荐 A；请回复 A、B 或 C。
```

直接生成 HTML 已经满足视觉确认要求，不需要为了得到 PNG 再引入截图工具，也不需要为了提供 URL 再启动另一套浏览器自动化。

## 七、验收命令

以下 Bash 示例使用占位路径，执行时替换为真实候选文件：

```bash
test -s path/to/option-a.html
test -s path/to/option-b.html
test -s path/to/option-c.html

iconv -f UTF-8 -t UTF-8 path/to/option-a.html >/dev/null
rg -n -e '<meta charset="utf-8"' -e '<title>' path/to/option-a.html
```

如果提供本地 URL，再额外验证：

```bash
curl -fsS http://localhost:<port> >/dev/null
```

URL 验证失败时只影响浏览器展示，不否定已经通过检查的独立候选 HTML。

## 八、完成标准

- 候选文件可独立打开；
- 每个候选有真实内容和实质差异；
- 用户不需要先解决浏览器连接问题才能选择；
- 选择结果由业务流程记录，而不是只留在浏览器事件中；
- 是否提交 Git 由当前项目和用户决定，视觉评审流程不得自动提交。
