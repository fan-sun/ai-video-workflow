# Vibe实际画面验收与返工

本文是[Vibe SOP](sop.md#3-逐幕实现与连续审看)的实际验收入口，落实[四层画面方法](motion_design.md)。使用本期已确认正文、切分、制作索引`visual_plan`指向的《画面编排.md》、时间表、实际源码及输出MP4；先核对索引中的活动版本与已有反馈。当前编排缺失、仍指向过期方案或当前幕只有概括性动作标签时，先按[编排要求](visual_methods.md#本期画面编排文件)补齐，不从已写代码倒推一份通过说明。检查记录复用本期索引或已有验收文件，不增加独立表单或用户审批。

本路线验收阶段同时调用[共用视觉检查方法](../common/visual_review.md)与[共用渲染技术检查](../common/render_verification.md)。共同方法只在上述文件维护；下文保留 Vibe 观看任务、结构、表现及返工要求。

## 实现与渲染入口

实现前读取索引当前的画面编排和字幕时间表；节奏或断点变化时，按[时间表规则](captions_timing.md#配合画面落实字幕与时间)同步后再渲染。原例小字、演示题材、十秒时长及构图不作为生产标准；字体和画面规则按[动态规范](motion_design.md)执行。

画面源保存在`course/acts/epNN_slug/`，索引填写`visual_source`、`visual_assets`及可选`sfx`。实现前读取[共用 HTML、素材与确定性契约](../common/visual_contract.md)。根画幅沿用[SOP默认规格](sop.md)，DUR 与 visual_timing.total_s 对齐；主字幕使用时间表导出的 SUBS，在稳定阅读区显示。制作中执行[共用视觉检查](../common/visual_review.md)，路线专属语义和表现仍按下方 Vibe 验收执行。

动作声可以是单声道或立体声。没有动作声的分段让`sfx`为空，渲染器使用实际静音音轨完成拼接；它不是伪造配音，也不会填入`audio`或`timings`。布局声明、首现和媒体检查按[共同渲染验收](../common/render_verification.md)。

```bash
npm run vibe:review -- course/episodes/03-topic-slug/制作索引.json --act 1 --check-only
npm run vibe:review -- course/episodes/03-topic-slug/制作索引.json --act 1 --range 0:6
npm run vibe:review -- course/episodes/03-topic-slug/制作索引.json --act 1
npm run vibe:review -- course/episodes/03-topic-slug/制作索引.json
```

Vibe画面审看直接输出high质量，所有前期小样、分幕及整片画面预览均不加BGM；仅全片画面确认后的最终高清发布版本按[配乐规则](audio_mix.md)混音。资源、局部预览和缓存按[共同渲染规范](../common/render_verification.md)，本节只规定路线交付顺序。每次交付对应视频、正式稿及索引`caption_preview`所指的逐屏字幕路径，注明版本与范围；需要解释正文结构时另给语义预览并标明用途。按用户安排逐幕审看，合并前检查全局起伏与所有幕间接点。

## 先验证连续小样

先渲染最容易暴露问题的连续小样，覆盖动作开始、过程、结果和相邻接点。优先选本期最需要验证的动作、关系揭示或空间转换，不因开头简单就只验证开头。使用实际整幕源码，不另做一套无法接入的漂亮静态样稿。按[方法落实检查](visual_methods.md#对照验证与返工)，将《画面编排.md》中当前幕的起点、中途过程、结果及接点与实际片段对照；在已有验收记录中说明哪一对象变化、空间接续和表现力已经兑现，哪些仍有差距。若待解决的是整幕组织停滞，小样须覆盖关键的相邻任务及其接续，单独改善材质、点题或某个动作不能关闭该问题；小样后仍须连看整幕。素材漂亮、程序能运行或标题完成入场，不算本期小样通过。

一轮设计自查后进入动画验证，检查含义及表现力，有具体问题再修。局部通过后重建受影响整幕；各幕已有有效版本时复用，合并前连看接点，合并后复查全片起伏。命令及逐幕交付顺序见[实现与渲染入口](#实现与渲染入口)。

## 实际检查与返工

1. 先按[画面编排与持续发展](motion_design.md#画面编排与持续发展)对照正文复核设计，再逐段核对时间表、源码与实际连续画面。逐项核对编排中的关键过程和结果，尤其是进入、交接、分离、揭示等动作有没有真的发生，不能以人物有移动或结果已摆好代替完整事件。核对所选方法是否兑现本期任务，不能以方法名称或动效数量替代实际过程。即使代码完整实现方案，设计本身仍是固定布局轮流添卡片、未完成任务转换或持续发展时，退回第二层重排；设计成立但计划中的主体过程、空间展开、关系变化或接点未落实时，修实现。涉及已确认内容时沿用既有确认要求。
2. 暂时遮住主字幕，保留理解动作必需的场景标注，检查能否认出主体在做什么、发生了什么变化及关键结果；具体事件与关系应由画面承担，概念名称及抽象含义可以由主字幕补足，不能靠不断换字代替主体过程，也不要求无标注猜出所有抽象关系。
3. 开场先正常速度看0～3秒，按[前三秒的观看理由](motion_design.md#前三秒的观看理由)指出实际可辨的处境、疑问或变化，再接着看后文是否兑现；只有装饰入场、无关特效或尚未建立观看理由时退回开场编排。不能凭“有动效”或一句吸睛文案判定通过。正常速度连续复查整幕及相邻接点，检查画面组织是否随讲解任务推进，再看节奏、动作幅度和关注点。不能只抽查各段末帧或逐个动画；跨幕长期沿用同一舞台也须合起来判断。无法完整播放时如实记录观察方式及待复查项，不把代码检查、自动播放到结束或抽帧比较写成已正常速度审看。
4. 按[动作表现方法](motion_design.md#动作怎样产生表现力)单独检查视觉表现：动作在实际观看大小下是否清楚，力度、速度变化和停顿是否符合本段目标，人物与道具是否统一，环境有无可辨空间与明暗，主次是否稳定。含义成立但动作微弱、拖沓、突兀、材质杂乱或背景抢戏时，写清具体时段与表现，修正后复看；不以“有特效”“分辨率够高”代替判断，也不要求安静段持续高潮。
5. 定位重复或停滞段的准确起止，说明其间主体过程、空间或关系新增了什么，按[时长口径](motion_design.md#时长只设上限)核对已设上限。若只为满足点题或总时长插入无字幕空档、顺延后文而未核对受影响事件和接续，先回到编排联动复查；无字幕本身不算问题，有效动画段应保留。若逐屏阅读估时被直接当作动作时长，或任务已结束却用旋转、推近、循环等填满剩余字幕时间，退回事件编排与阅读窗口联动重排，更新实际时间表及逐屏预览；不能只整体加速或快闪字幕。任务已结束却继续重复弹出、高亮或刷屏，必须压缩或重排；任务尚未完成但结构不适合表达，应重组场景。长场景有持续发展可保留，不按固定秒数切镜；像素运动、动画条数和时间轴跑满不能抵消失败。
6. 比较实际MP4的开始、中途、落定帧及过渡中途，检查对象身份、空间联系与视觉重心。点题、结果揭示和回扣应有对应变化，不能只靠读标签才能辨认；首次点题还须按[首次点题时间](motion_design.md#首次点题时间)核对实际完成登场的全片时刻是否落在16～19秒（含边界）。在已有验收记录注明实际视频路径、观察到的开始与完成时刻及对应帧位置，核对名称完整可读、成为焦点和主要入场落定；此前已完成后一直停留，不算窗口内首次完成。越界须重排并复核，实际与登记不一致时同步修正索引和时间表。只核过登记数据、源码或技术报告时，实际点题状态仍为待核验，不得登记通过。按[主题登场与特效选择](motion_design.md#主题登场与特效选择)核对本期选效依据及揭示的醒目程度。对承担知识点展示的主视觉，另按[阅读停留](motion_design.md#知识点展示后的阅读停留)核对实际完整落定时刻与后续接续时刻：其间须有连续至少1秒完整可读、保持视觉重点的阅读窗口，纯展示不超过2秒。记录实际视频的对应时刻；不足1秒、提前遮挡或转移焦点时，退回受影响时间安排与画面修正并复看。背景微动不算新的内容推进；检查程序目前不自动识别这段有效阅读窗口，不能只凭登记值或技术检查通过放行。
7. 按[结尾收束](motion_design.md#结尾收束)从末幕起点连续复查到最后落定，对照开场处境、具体原文与本期收束目标，分别记录认识是否有依据、情绪期待是否得到回应。指出正文、人物反应或对象关系与节奏怎样共同形成该变化；实验正确、关系图成立、标题醒目或一句金句均不能单独放行。整幕变成讲解者归纳道理而丢失观众的情绪期待时，退回受影响整幕的正文或编排审查，不能仅改最后几字、追加安慰或标注“人物释然”。设计成立但过程未兑现，或结果未形成却只剩微动、蒸汽、慢推及无关特效时，按第1项修实现或退回设计。已形成有依据的认识或情绪落点后可以安静停留，不强加高潮、励志或通用片尾。
8. 按[手机观看字号](motion_design.md#手机观看字号)与[分屏规则](motion_design.md#主字幕长度与分屏)，在约360～480px宽的实际 MP4 中复核80px主字幕、至少64px必要文字及本路线分屏。通用动作标注、缩放可读性和遮挡检查执行[共同阅读检查](../common/visual_review.md#阅读动作与遮挡)；Vibe 还须核对标注是否帮助理解持续发展的事件、音效是否对应对象和落点、混音后动作声有无被淹没。字号不符、把必要文字当装饰或分屏未落实时须返工。
9. 执行前述共同视觉和技术检查。Vibe 结构与表现判断须单独成立，技术结果不能抵消前面各项的失败。

文字专项还须对照[文字任务与常驻图层](motion_design.md#字幕和声音保持主次)清点实际画面：没有内容作用、也无用户明确要求的系列名、期号及栏目装饰应删除；必要字幕与主体标注继续保留。修改后复查实际导出，不用已修改的源码替旧视频通过验收。交付前逐条对照`caption_preview`与实际字幕，屏数、顺序和断点应一致；只有全文一样、预览却仍为大段正文时，重跑时间表导出后再交付。

在现有制作索引或验收记录中标明对应编排段落、实际视频版本、具体时段、计划任务、实际表现和结论；将记录链接回《画面编排.md》，并区分编排已完成、已实现、已验证及用户确认范围。指出哪一主体过程、空间或关系变化兑现了观看任务；必要标注另记移动中途和缩小显示的核对位置。画面组织、动作解释、视觉表现与技术结果分别记录，任一失败或未核实不能登记整体通过，不只复述“标题居中、已加动效、符合参考风格”。逐段成立后再看全片起伏与幕间接点；局部素材、背景或某个动作获认可，不等同于整幕或整片通过。

## 技术检查的范围

Vibe使用high质量审片及视觉时间表；当前无旁白版本不要求TTS、教学开场、章节栏、片尾静音或嵌入首帧封面。公共预检、资源、缓存、布局、首现、运动筛查和解码执行[共同渲染规范](../common/render_verification.md)。本表只列Vibe专属检查。

| 检查 | 自动覆盖及适用范围 | 仍需实际画面核对 |
|---|---|---|
| 正文与字幕 | `split:vibe`按Vibe规则生成初切草稿及待处理项；`timeline:vibe`校验正文覆盖、时段及24字上限，从同一时间表导出逐屏预览。review及发布检查核对已确认来源和已登记预览的逐条对应关系 | 自动切分仍需人工复核专名、问句与断点；文字用途、缩放后的有效字号、每行字数、语义、行宽和阅读时间须看实际画面，现有工具不自动判定所有HTML／SVG／Canvas文字的有效字号；显示层不能合并字幕或保留旧字形成超量同屏 |
| 首次点题窗口 | 时间表导出、review预检和发布检查验证`topic_reveal`的数值、顺序、全片16～19秒完成窗口及索引与导出的对应关系；仅技术短示例豁免 | 程序不能识别名称是否完整可读、成为焦点及动作落定，必须按第6项审看实际画面；登记合规不等于实际合格 |

主体停滞检测在本路线可选；采用时在 acts[].motion_check 记录真实主体区域、阈值及理由，未配置写未执行。无论是否采用，均必须完成上述 Vibe 连续发展与表现审看；不把公共工具的默认参数当作场景时长上限。

## 局部返工与确认范围

同一问题反复出现时，回到整段事件编排，不继续加缩放、摆件和小幅漂移。局部返工和认可范围按[共同执行规则](../common/execution.md#版本与修改)及[视觉证据范围](../common/visual_review.md#检查方式与通过范围)。每轮只关闭实际修复并核验的问题；只改字幕不能登记整段视觉返工完成，不每轮新建外部评审稿。

完整配乐版仍按[SOP最终审片与发布](sop.md#6-确认高清审片版生成并验收发布包)获取对应文件的用户确认；技术报告、AI视觉判断与用户认可分别保存。
