# Vibe实际画面验收与返工

本文是[Vibe SOP](sop.md#3-把画面设计成连续发生的过程)的实际验收入口，落实[四层画面方法](motion_design.md)。使用本期已确认正文、切分、画面编排、时间表、实际源码及输出MP4；先核对索引中的活动版本与已有反馈。检查记录复用本期索引或已有验收文件，不增加独立表单或用户审批。

## 先验证连续小样

先渲染最容易暴露问题的连续小样，覆盖动作开始、过程、结果和相邻接点。优先选本期最需要验证的动作、关系揭示或空间转换，不因开头简单就只验证开头。使用实际整幕源码，不另做一套无法接入的漂亮静态样稿。

一轮设计自查后进入动画验证，检查含义及表现力，有具体问题再修。局部通过后重建受影响整幕；各幕已有有效版本时复用，合并前连看接点，合并后复查全片起伏。命令及逐幕交付顺序见[SOP画面阶段](sop.md#3-把画面设计成连续发生的过程)。

## 实际检查与返工

1. 先按[画面编排与持续发展](motion_design.md#画面编排与持续发展)对照正文复核设计，再逐段核对时间表、源码与实际连续画面。即使代码完整实现方案，设计本身仍是固定布局轮流添卡片、未完成任务转换或持续发展时，退回第二层重排；设计成立但计划中的主体过程、空间展开、关系变化或接点未落实时，修实现。涉及已确认内容时沿用既有确认要求。
2. 暂时遮住主字幕，保留理解动作必需的场景标注，检查能否认出主体在做什么、发生了什么变化；抽象含义可以由主字幕补足，不能靠不断换字代替主体过程，也不要求无标注猜出所有抽象关系。
3. 正常速度连续复查整幕及相邻接点，检查画面组织是否随讲解任务推进，再看节奏、动作幅度和关注点。不能只抽查各段末帧或逐个动画；跨幕长期沿用同一舞台也须合起来判断。无法完整播放时如实记录观察方式及待复查项，不把代码检查、自动播放到结束或抽帧比较写成已正常速度审看。
4. 按[动作表现方法](motion_design.md#动作怎样产生表现力)单独检查视觉表现：动作在实际观看大小下是否清楚，力度、速度变化和停顿是否符合本段目标，人物与道具是否统一，环境有无可辨空间与明暗，主次是否稳定。含义成立但动作微弱、拖沓、突兀、材质杂乱或背景抢戏时，写清具体时段与表现，修正后复看；不以“有特效”“分辨率够高”代替判断，也不要求安静段持续高潮。
5. 定位重复或停滞段的准确起止，说明其间主体过程、空间或关系新增了什么，按[时长口径](motion_design.md#时长只设上限)核对已设上限。任务已结束却继续重复弹出、高亮或刷屏，必须压缩或重排；任务尚未完成但结构不适合表达，应重组场景。长场景有持续发展可保留，不按固定秒数切镜；像素运动、动画条数和时间轴跑满不能抵消失败。
6. 比较实际MP4的开始、中途、落定帧及过渡中途，检查对象身份、空间联系与视觉重心。点题、结果揭示和回扣应有对应变化，不能只靠读标签才能辨认；首次点题还须按[首次点题时间](motion_design.md#首次点题时间)核对实际完成登场的全片时刻。按[主题登场与特效选择](motion_design.md#主题登场与特效选择)核对本期选效依据、揭示的醒目程度及纯展示停留，不把照搬样片或背景微动当作通过依据。
7. 按[结尾收束](motion_design.md#结尾收束)从末幕起点连续复查到最后落定，对照开场处境、具体原文与本期收束目标，分别记录认识是否有依据、情绪期待是否得到回应。指出正文、人物反应或对象关系与节奏怎样共同形成该变化；实验正确、关系图成立、标题醒目或一句金句均不能单独放行。整幕变成讲解者归纳道理而丢失观众的情绪期待时，退回受影响整幕的正文或编排审查，不能仅改最后几字、追加安慰或标注“人物释然”。设计成立但过程未兑现，或结果未形成却只剩微动、蒸汽、慢推及无关特效时，按第1项修实现或退回设计。已形成有依据的认识或情绪落点后可以安静停留，不强加高潮、励志或通用片尾。
8. 按[手机观看字号](motion_design.md#手机观看字号)及[主字幕长度与分屏](motion_design.md#主字幕长度与分屏)检查正文字幕，再按[动作标注与解释](motion_design.md#动作标注与解释)追踪必要名称、数字和解释：在正常速度及约360～480px宽的实际MP4缩小画面中，动作与含义能否在同一关注区域被理解。阅读时段内按最终缩放结果核对80px主字幕及至少64px必要文字，不能只看源码字号；更小文字须确属无需读懂的纹理或细节。检查移动中途、交叉处和最小尺度的遮挡与可读性，不能只看停稳帧或暂停放大阅读；字号不符、把必要文字当装饰、标注缺失、不同步、跨屏找解释或移动中读不清，均须修正并重看完整路径。另核对音效对象和密度，混音后检查动作声是否被音乐淹没。
9. 再结合布局、首次可见、反向定位、完整解码、尾帧与接点检查。像素一直在变不证明叙事或审美达标；技术检查通过不能抵消前面各项的失败。

文字专项还须对照[文字任务与常驻图层](motion_design.md#字幕和声音保持主次)清点实际画面：没有内容作用、也无用户明确要求的系列名、期号及栏目装饰应删除；必要字幕与主体标注继续保留。修改后复查实际导出，不用已修改的源码替旧视频通过验收。交付前逐条对照`caption_preview`与实际字幕，屏数、顺序和断点应一致；只有全文一样、预览却仍为大段正文时，重跑时间表导出后再交付。

在现有制作索引或验收记录中标明具体时段、计划任务、实际表现和结论，指出哪一主体过程、空间或关系变化兑现了观看任务；必要标注另记移动中途和缩小显示的核对位置。画面组织、动作解释、视觉表现与技术结果分别记录，任一失败或未核实不能登记整体通过，不只复述“标题居中、已加动效、符合参考风格”。逐段成立后再看全片起伏与幕间接点；局部素材、背景或某个动作获认可，不等同于整幕或整片通过。

## 技术检查的范围

Vibe使用high质量审片、单幕2个worker、分幕串行及已有缓存。当前无旁白版本不要求TTS、教学A/B/C开场、章节栏、片尾静音或嵌入首帧封面。技术实现复用[通用渲染工具](../common/render_verification.md)，按本表判断结果，不照搬该文档的教学默认顺序或standard质量。

| 检查 | 自动覆盖及适用范围 | 仍需实际画面核对 |
|---|---|---|
| 正文与字幕 | `split:vibe`按Vibe规则生成初切草稿及待处理项；`timeline:vibe`校验正文覆盖、时段及24字上限，从同一时间表导出逐屏预览。review及发布检查核对已确认来源和已登记预览的逐条对应关系 | 自动切分仍需人工复核专名、问句与断点；文字用途、缩放后的有效字号、每行字数、语义、行宽和阅读时间须看实际画面，现有工具不自动判定所有HTML／SVG／Canvas文字的有效字号；显示层不能合并字幕或保留旧字形成超量同屏 |
| 布局与时长 | `lint/validate/inspect`及入口核对根画幅、DUR、时间表边界、越界与警告 | 不能只看稳定帧；有意裁切仅标最小局部，移动中途仍要检查，不豁免整幕 |
| 首次可见 | `check_course_reveal.mjs`核对`data-reveal-at`标注对象的入场前后及倒退状态；长入场可设置`data-reveal-duration` | 从编排独立列出预期入场对象，核对标注覆盖、父子遮挡和信息是否提前出现；无标注返回`not_applicable`，须记录未执行，不能写成通过 |
| 主体停滞 | 仅配置`acts[].motion_check`时运行像素停滞检测，记录主体区域、所选阈值及报告；未配置时明确记未执行 | 检测区域覆盖实际主体，不裁成小转轮。工具缺省6秒是技术筛查参数，不是Vibe场景上限；需要时明确选阈值和理由，不以放宽阈值消除真实失败。检测未运行或通过均不能免除连续画面审看 |
| 实际媒体 | 完整解码、规格、音轨及发布文件哈希核验 | 抽取实际MP4尾段与最后一帧，核对接点中途、材质和文字是否消失；源HTML能定位到末态不能证明导出尾帧正常 |

首次可见还应覆盖场景刚开始、计划入场前一帧、入场落定后，以及先跳到片尾再倒退的同一时点。技术注释不能替代实际画面，不能从动画代码反推一份预期清单来自证正确。观察方式与证据范围如实记录；抽帧、自动播放和用户正常速度审看分别登记。

## 局部返工与确认范围

同一问题反复出现时，回到整段动作设计，不继续加缩放、摆件和小幅漂移。局部返工或复用旧段前，先读取已有反馈与验收记录，区分已认可、未验证、已否定的部分。已认可且不受本轮修改影响的部分继续复用；未验证部分可暂留但仍待验，已否定部分不能当作有效版本沿用。不能因本轮未修改或技术检查通过，就把旧段落视为已认可。

每轮只修改受影响段，复查其连续过程及前后接点；在已有记录中只关闭本次实际解决并核验的问题，其余未解决项继续保留。例如只修字幕，不能登记点题或整段视觉返工完成。完成局部验证后重建该幕，其他有效幕复用，不每轮新建外部评审稿。

完整配乐版仍按[SOP最终审片与发布](sop.md#6-确认高清审片版生成并验收发布包)获取对应文件的用户确认；技术报告、AI视觉判断与用户认可分别保存。
