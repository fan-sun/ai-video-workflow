# Vibe旁白预览、字幕与时间表

用于[SOP第1、2步](sop.md#1-先写观看主线和稿件)。先程序生成语义预览和字幕初切，内容确认后先编排连续画面，再落实逐屏时间；不从初切屏数反推场景或片长。

## 逐幕生成旁白语义预览

正文审查通过后，按[共用旁白语义预览](../common/narration_preview.md)实际调用现有程序，按本期1～6幕生成、复核并汇总整期预览；格式、路径、执行证据和交付核对均由该文档维护。即使不生成旁白音频也要执行，不用手工段落或逐屏字幕代替。语义句组的长度不决定Vibe单屏字数、镜头边界或时长。

## 程序初切与人工复核

上述旁白语义预览已由程序生成并核对后，再运行Vibe专用程序生成逐屏字幕初切草稿。这里不能将语义预览原样当作屏幕字幕，不使用教学36字符及配音短句合并的默认输出作为分屏结果：

```bash
npm run split:vibe -- course/episodes/03-topic-slug/制作索引.json
```

命令在本期索引同目录生成`字幕初切草稿.json`，按幕列出`source_text`、每屏`captions`及`review_notes`，保留标点；`start`、`end`、`total_s`均为`null`，不按字数自动排成片时间，也不生成TTS字段或用户确认。程序复用已有标点与成对引号断句能力，按Vibe字数口径组合分句，短句只在当前句内合并；完整问句尽量保持联系，数字分组、时间及引号内的专名不按内部逗号硬切。程序不能识别所有专名或语义，不能因此省略人工复核。

退出码`0`表示初切完成且没有长度等专项提示，不表示人工复核通过；`3`表示草稿已生成但有待处理提示，须逐项检查；`1`表示执行失败。长度提示按[分屏标准](motion_design.md#主字幕长度与分屏)逐项复核；无法安全切分时保留原文并明确报错，不截断专名、不删词。相同输入可重复运行；现存草稿与新结果不同时拒绝覆盖，改用`--out course/episodes/03-topic-slug/字幕初切草稿-v2.json`另存，不覆盖人工修改。

此处先复核句意、指代、完整问句、专名与单位，保留生成依据；初切及复核结果仍是可调整草稿，不据此锁定屏数、动作边界或整片时长。先按[画面编排要求](visual_methods.md#本期画面编排文件)组织连续事件，再结合实际动作与阅读窗口调整断点和起止时间，形成统一的`captions`；动画与逐屏预览均读取这份时间表，不能在动画脚本再维护另一套文字数组。初切与人工复核分别如实记录；从人工数组导出文件不等于运行过程序初切。

沿用既有内容和切分确认节点，同轮交付讲解稿与程序生成的整期旁白语义预览；若附字幕初切草稿，单独标明类型及待复核状态，不能用它替代旁白预览。用户索要“字幕切分”时，交付每条对应一屏的文件；时间表尚未生成时可交付明确标注状态的初切草稿，不能只给正文段落预览。缺少语义预览的程序执行依据、汇总与逐幕输出不符或交付类型错误时，按共用预览规则返工后补交。用户确认后，助手记录`content_approval: {"confirmed": true, "statement": "用户原话"}`；调整涉及改词、增删正文时，仍先按原要求确认，不增加审批节点。

## 内容确认与版本绑定

内容与切分确认完成后执行一次版本绑定，此时不需要画面或时间表：

```bash
npm run timeline:vibe -- course/episodes/03-topic-slug/制作索引.json --bind-approved-source
```

命令先核对正式稿与预览，再保存`content_approval.source_sha256`，记录本次认可的各幕正文及切分版本；它不创建用户确认。原文或切分变化后，普通时间表、review和发布检查会拒绝旧绑定，须先按已有改稿确认流程处理再更新绑定，不能用此参数直接消除未确认改稿的报错。更新正文绑定会使旧的整片审片和发布确认失效；相同版本重复绑定保留已有确认。已确认的旧期次可在核实现存文本确为认可版本后补绑定，不重复索取未变化内容的确认。技术示例使用`example.technical_only`明确跳过真实正文确认绑定，不用它绕过正式制作检查。

这里绑定的切分版本是`split_preview`所指的语义预览。后续只调整逐屏断点、换行或时间且不改变正文及语义预览时，不重绑正文或重复索取内容确认；更新实际时间表、逐屏预览及受影响画面后，按原审片范围复核。

## 配合画面落实字幕与时间

当前幕的[连续画面编排](visual_methods.md#本期画面编排文件)自查成立后，粗排全片的动作、揭示、阅读与停留时间，检查是否过长、重复或主题出现太晚；在制作索引的`topic_reveal`填写`start_s`与`complete_s`，均为相对正片0秒的累计秒数；开始不得晚于完成，完成必须在16～19秒内（含边界）且不超出整片。按[首次点题时间](motion_design.md#首次点题时间)编排后再逐幕实现并审看，程序将这两个时刻原样导出到整期时间表。四幕总时长是本期设计结果，不以每句字数、参考片重拍点或TTS读完速度机械决定。

时长与计时边界按[动态规范](motion_design.md#时长只设上限)执行；知识点展示完成后的阅读窗口按[阅读停留规则](motion_design.md#知识点展示后的阅读停留)在同一时间表登记完成、停留结束与接续时刻。

讲解不必铺满时间轴。字幕可以在仍有阅读或情绪作用时保留，也可以清除，让动画独立推进情境、动作或关系；未来加入人声也允许无讲解的空段。前文提前讲完而点题窗口未到时，应由有内容发展的画面承接，不冻结旧字幕、慢放或循环凑秒数；这一原则适用于全片。字幕之间留空不等于漏稿，已确认正文仍须完整覆盖。

将初切草稿与连续事件对照，调整字幕断点、出现时机及阅读窗口，再按幕保存画面时间表，填写本轮计划的`total_s`及每屏`start/end`，复核提示的处理理由留在已有记录中。一句字幕可以跨多个动作，一个连续事件可以承接多屏字幕，换字幕不指挥换场景。若动作已经完成而文字尚未读完，先检查提前呈现、跨后续相关动作阅读或重分屏是否合适，也可保留有理解或情绪作用的停留；不拉长无进展的旋转、推近或循环来凑时长。若读字与关键动作争夺注意力，应调整事件安排与阅读窗口，不能将字幕快闪塞进动画；涉及改词、增删正文时仍先确认。时间未确定的`null`不能进入渲染。索引填写`acts[].visual_timing`，不是TTS timings；以下仅展示时间表结构，不是固定分屏模板：

```json
{
  "total_s": 8,
  "source_text": "这些投入收不回来。未来的时间还能选择。",
  "captions": [
    {"id": "c01", "start": 0, "end": 4, "text": "这些投入收不回来。"},
    {"id": "c02", "start": 4, "end": 8, "text": "未来的时间还能选择。", "emphasis": ["时间"]}
  ]
}
```

字幕必须能读完，时段不重叠且不超出本幕；拼接字幕去掉标点和空白后须与`source_text`一致。重点放在具体词上，只强调必要的词，每幕通常不超过三个，不要求每句着色。源码的`const DUR`和根`data-duration`与`total_s`一致。

时间表的`captions`应落实实际逐屏显示：先按保留标点的原文确定分屏，再填写各屏真实起止时间，最后显示时去标点；切分预览的一条可以对应多条时间表字幕，显示层按时间表逐屏切换。分屏顺序、单屏长度、双行条件和实际画面验收统一按[主字幕规范](motion_design.md#主字幕长度与分屏)执行，不把较长的讲解稿语义组直接当作必须整句同屏的字幕。

准备所有时间表并登记`topic_reveal`后执行：

```bash
npm run timeline:vibe -- course/episodes/03-topic-slug/制作索引.json
```

正式视频缺少`topic_reveal`、登记值越界或时间顺序错误时，时间表导出明确失败；`review`、`publish:package`及独立`check:release`还核对索引与整期时间表的点题值一致。旧期次重新制作或发布时须补充真实记录；不自动填成17秒。仅已有`example.technical_only`技术短示例沿用豁免，不代表正式视频通过。程序只检查登记数据，名称何时真正完整可读须按[画面验收](visual_review.md)核实。

命令对照已绑定的正式稿、语义预览与各幕`source_text`，校验字幕覆盖、时段及同屏最多24字，再从同一组`captions`生成连续的`整期时间表.json`与`逐屏字幕预览.json`，登记索引的`timeline_summary`、`caption_preview`和总时长。逐屏预览仍用`act1`等数组保存，每条恰好对应一屏，顺序、文字和标点与实际时间表一致；语义预览与逐屏预览必须使用不同文件路径。

连续小样及整幕审看中的时间或断点变化后重跑该命令，不手改导出的预览，也不沿用旧边界。review和发布检查会逐条核对已登记的逐屏预览，仅全文拼接相等但屏数或断点不同仍须重新导出。未登记该字段的历史索引保留兼容，重新制作时运行时间表入口即可补齐。字数和导出检查不代替每行长度、实际显示是否累计旧字、阅读时间与画面主次，具体按[字幕规范](motion_design.md#主字幕长度与分屏)执行。
