# Vibe知识讲解路线

这条路线把现象、词语、谚语或效应做成以连续动画、屏幕文字和声音推动的知识短片。优先让观众愿意看下去，在共鸣、疑惑、反差和发现中理解一个认识。需要系统学会概念或操作时，使用[教学路线](../sop.md)。主题和路线分别选择，AI概念同样可以用Vibe表达。

默认视频1920×1080、30fps，先制作无人声旁白版本；封面独立为3:4。画面与文字阅读决定时间，声音克隆不是前置条件。制作分段默认四幕，可按内容调整为1～6段，不为凑幕数或固定时长增加内容。

## 从这里开始

用户已经指定路线或主题时直接沿用。用户未指定主题时，AI先按选题规则检查重复，选择一个合适主题，说明选择与讲解角度，再继续；不要每次都要求用户从词表中选择。主题确认和后续具体稿件确认分别记录。

```bash
npm run doctor -- --route vibe
npm run topic:check -- --topic "主题词" --summary "观看入口与讲解角度"
npm run init:episode -- 03-topic-slug --topic "主题词" --route vibe
```

查重缺少可选语义Key时沿用[选题规则](../common/topic_selection.md)，如实记录未执行项。初始化建立`route: "vibe"`、`production_contract: "current"`的索引，不能用历史契约或假配音绕过检查。没有`route`字段的已有课程继续使用教学路线；初始化不把旧期次自动切换。

环境需要Node、Python、FFmpeg、Chrome及可用NVENC，与教学路线复用现有渲染依赖。Vibe的doctor只检查Python可运行，不检查VoxCPM、模型或参考声音。按[安装文档](../common/setup.md)准备通用环境即可。

## 1. 先写观看主线和稿件

先说明观众为什么停下、期待看到什么、哪一处产生发现、结尾怎样回应开头。情绪锚点可以是舍不得、失控或误解，道具不必贯穿全片。通常从具体处境、问题或反常现象进入，较早交代主题；不要先解释一分钟，才告诉观众在讲哪个概念。

表达以通俗、吸引注意和容易理解为先，保留必要事实和因果关系，不要求像科研报告一样展开所有细节。引用研究先核实原始条件、人数与结果，再用观众听得懂的选择和结果改写；不添加没核实的倍数或把问卷选择写成真实投资。一个生活例子可以建立代入，另一个例子或研究提供反差，结尾给观众可理解的判断方式或新发现。

复用[内容审查与润色](../common/script_content_review.md)中的事实核验、因果与指代、连续顺读及单次`copy-editing`润色。Vibe的主干是本期观看问题与发现，不要求覆盖资料的全部分类，也不套用教学的固定点题句、四幕结构和TTS切分要求。具体改稿先给用户确认，再改文件。讲解稿、切分预览和实际字幕须覆盖相同原文；显示字幕去掉标点，但不能因此删句、改词或让道具标签取代完整文字。完整问句优先保留完整语义，不因短句偏好硬拆。

用户确认后，助手在制作索引记录`content_approval: {"confirmed": true, "statement": "用户原话"}`。示例使用`example.technical_only`，不伪造用户确认。正式讲解稿放在`course/scripts/`，本期切分与索引放在`course/episodes/NN-slug/`。

## 2. 全片统筹时间，再逐幕制作

先粗排全片的阅读、动作、揭示与停留时间，检查是否过长、重复或主题出现太晚；再逐幕实现并审看。四幕总时长是本期设计结果，不以每句字数、参考片重拍点或TTS读完速度机械决定。

每幕保存真实的画面时间表，填写索引的`acts[].visual_timing`，不是TTS timings：

```json
{
  "total_s": 8,
  "source_text": "这些投入收不回来。未来的时间还能选择。",
  "captions": [
    {"id": "c01", "start": 0, "end": 4, "text": "这些投入收不回来。"},
    {"id": "c02", "start": 4, "end": 8, "text": "未来的时间还能选择。", "emphasis": ["时间"]}
  ]
}
```

字幕必须能读完，时段不重叠且不超出本幕；拼接字幕去掉标点和空白后须与`source_text`一致。重点放在具体词上，只强调必要的词，每幕通常不超过三个，不要求每句着色。源码的`const DUR`和根`data-duration`与`total_s`一致。

准备所有时间表后执行：

```bash
npm run timeline:vibe -- course/episodes/03-topic-slug/制作索引.json
```

命令校验各幕字幕并写入连续的`整期时间表.json`、索引的`timeline_summary`和总时长。时间或切分变化后先重跑，不沿用旧累计边界。

## 3. 把画面设计成连续发生的过程

按[动态画面要求](motion_design.md)先设计开始、过程和结果，再安排场景、镜头、背景和声音。字幕不变时也可以丰富对应的动作与情境，不为填空增加无关动作。

视频风格先确定配色、字体、形象、材质与运动感觉；可以选择示例或让AI提出适合主题的方向，用户选定后继续。Vibe不强制使用教学A/B/C固定开场或视频章节覆盖栏。各幕仍要共享视觉语言，具体环境随内容改变。

画面源保存在`course/acts/epNN_slug/`，索引填写`visual_source`、`visual_assets`及可选`sfx`。HTML使用现有HyperFrames契约：

- 根元素标明`data-composition-id="main"`、`data-start="0"`、画幅和时长。
- 单个暂停GSAP时间轴注册到`window.__timelines["main"]`，正向和反向定位一致。
- 放置唯一`/*__SUBS__*/`，用注入后的`SUBS`更新主字幕，文字层保持稳定阅读区。
- 使用本仓库字体路径；外置素材通过`visual_assets`进入构建，参考[技术示例](../../../examples/vibe-knowledge/README.md)。

动作声可以是单声道或立体声。没有动作声的分段让`sfx`为空，渲染器使用实际静音音轨完成拼接；它不是伪造配音，也不会填入`audio`或`timings`。有意裁切只声明最小局部元素，沿用布局、首现、解码和运动检查，不能豁免整幕。

```bash
npm run review -- course/episodes/03-topic-slug/制作索引.json --act 1 --check-only
npm run review -- course/episodes/03-topic-slug/制作索引.json --act 1 --range 0:6
npm run review -- course/episodes/03-topic-slug/制作索引.json --act 1
npm run review -- course/episodes/03-topic-slug/制作索引.json
```

Vibe审片直接输出high质量，浏览器GPU、NVENC、每幕2个worker、分幕串行；有效分幕沿用现有哈希缓存。局部预览不登记整幕完成，其他有效幕不用重渲染。每次交付对应视频、正式稿及切分路径，按用户安排逐幕审看；合并前检查全局起伏与所有幕间接点。

## 4. 分轨试听，再按确认比例混音

动作声对应具体可见动作，切镜头不自动加沙沙声。先选音色，再检查音量、落点和密度。音乐、人声与动作声分别处理；先完成无人声版本，可选人声在成片后再讨论。需要精确踩音乐时提前确定素材和片段，后加音乐不声称已经按音乐重拍制作。

在索引填写`bgm.file`，路径可使用本地已有音乐；`gain`先留空。生成试听页：

```bash
npm run preview:music -- course/episodes/03-topic-slug/制作索引.json
```

打开输出的`配乐试听.html`，一边播放一边调音乐，复制选定比例交给助手。页面引用未混音乐的`review_base_output`，避免双重叠加；暂停和拖动时音乐同步。初始试听值不代表用户选定。

用户确认后记录例如：

```json
"bgm": {
  "file": "course/episodes/03-topic-slug/music.wav",
  "source_gain": 1,
  "gain": 0.25,
  "approval": {"confirmed": true, "statement": "动作100%，音乐25%"}
}
```

这只是数值示例，25%不是固定推荐。增益按线性比例，不未经要求归一化、压低原声或加淡入淡出。音乐从0秒播放至视频结束；当前入口要求音乐足够长，短音乐需先明确制作循环版本或替换。

```bash
npm run mix -- course/episodes/03-topic-slug/制作索引.json
```

命令复制视频编码数据，另存配乐版并检查解码、声道、起止、时长和削波，保留底片与原音乐。先核验临时候选，通过后才替换输出；失败不覆盖已有配乐版。混音版更新`review_output`，需要审看这份完整最终视频；没有BGM时直接审看底片。

完整review始终写当前版本的无BGM底片，不把配乐路径当作画面输出。重建画面或改变混音后，旧发布验收状态失效；未变化的混音文件保留已有确认。已确认内容需要修改时另存新版本，复用未改动的媒体，再执行受影响阶段。

## 5. 独立封面与发布文案

封面选择代码制图或AI生图。先提交主信息与构图供用户确定，再生成一版实际图片。AI生图使用可用工具或用户提供的图；缺少能力时明确说明并选择可执行方式，不把文字提示词当作已经生图。

当前发布封面要求3:4，与16:9视频分别设计，不直接裁切横图。主题明确、主体辅助、缩小后可读；是否只用主题词、字数、人物、风格由本期决定。AI生成后检查文字、画幅、肢体和裁切，记录实际像素，不把插值放大称为2倍渲染。交付必须含可点击原图；用户确认后复制到发布目录，记录`cover_selection`、`cover_output`与`cover_upload_output`。不覆盖已有确认图，独立封面不自动插入视频前0.5秒。

发布TXT仍包含标题、发布文案、标签、视频总结、视频章节，顺序与[发布交付](../common/release_delivery.md)一致。Vibe专属规则：

- 标题为`Vibe知识大赏｜主题词：短问题或反差`，冒号后含标点最多15个字符，通常10～12个汉字即可，不为凑长度加词。
- 正文简短展开同一个矛盾，结尾保留一个有力的问题，避免重复反问。只改发布文案不自动改讲解稿或视频。
- 标签包含`#Vibe知识大赏`及与主题相关的标签；不强制`#AI基础`或`#深度讲解`。
- 总结50～200个非空白字符，独立解释核心认识和必要边界，不照抄发布正文。
- 章节使用索引中的短标题，按正式整期时间表四舍五入到整秒，不提前估计。

## 6. 确认高清审片版，生成并验收发布包

完整最终视频获用户确认后，助手在`review_approval`保存`confirmed: true`、用户原话与该文件的SHA256。发布入口拒绝确认后变动的文件；示例例外只表示技术核验，不创建用户认可。

```bash
npm run publish:package -- course/episodes/03-topic-slug/制作索引.json
```

发布入口直接复制已确认的high审片版，将选定的独立封面复制为同目录`cover.png`，保留同版文案，并执行路线发布检查。它核对文件、版本、规格、时长、章节、文案、音轨一致、3:4封面和台账；不要求片尾静音或首帧嵌入封面。通过后保存`release-check.json`，真实登记`publish_bundle.complete`。

修改文案、封面或索引后独立复查：

```bash
npm run check:release -- course/episodes/03-topic-slug/制作索引.json
```

输出仍在`pipeline/output/course/epNN_slug/vK/`。公开上传须按用户授权另行执行，不把本地交付写成已公开发布。生成视频、用户声音、音乐、模型、密钥和个人路径继续本地忽略；生产规则和通用工具随仓库分发。
