# Vibe知识讲解路线

用连续画面、屏幕文字和声音，让观众在具体锚点、反差和情绪起伏中直观理解一个概念。以吸引力和观看推进为首要标准，不为解释周全反复铺垫或重述结论；材料只取表达需要的部分。详细写法在[稿件创作与审查](script_writing.md)。需要系统学会知识或操作时，使用[教学路线](../sop.md)。

画面中的事件、对象关系与结果承担主要解释，字幕补充关键含义、命名概念和点透发现。观众应能认出具体发生了什么，不要求脱离文字猜出准确概念。

默认1920×1080、30fps、先无人声，声音克隆不是前置条件；封面独立为3:4。制作分段默认四幕，可按内容调整为1～6幕，不为凑幕数或固定时长增加内容。先编排连续画面，再落实字幕和时间，不以语义句组或初切屏数决定片长。

开始或恢复时，读取[共用执行规则](../common/execution.md)、`course/episodes.json`和本期制作索引，按真实进度进入下列阶段，并读取该阶段链接的完整规则。已有确认在内容未变化时继续有效，不新增审批。文件位置按[选题登记](../common/topic_selection.md)，新成片默认在`pipeline/output/vibe/epNN_slug/vK/`，历史路径按[输出兼容规则](../common/output_paths.md)保留。

## 从这里开始

主题类型与表达路线分别选择，AI概念同样可以用Vibe表达。沿用用户指定的主题与路线；没有主题时，先查重并选题，说明角度后继续。主题确认与具体稿件确认分别记录。按[安装文档](../common/setup.md)准备环境，执行：

```bash
npm run doctor -- --route vibe
npm run topic:check -- --topic "主题词" --summary "观看入口与讲解角度"
npm run vibe:init -- 03-topic-slug --topic "主题词"
```

精确查重通过后初始化；缺少语义Key按[查重规则](../common/topic_selection.md#选题与查重)记录。新索引保留`route: "vibe"`和`production_contract: "current"`，不以历史契约或假配音绕过检查。没有`route`字段的旧期次仍按教学路线，初始化不自动切换。

Vibe doctor检查可运行的Python，不检查VoxCPM、模型或参考声音；通用渲染仍需FFmpeg、Chrome及可用NVENC。进入最终高清发布版配乐阶段时再查[固定音乐文件](audio_mix.md#固定设置)，doctor不检查它，仓库也不附带；前期预览不以音乐文件为前置条件。技术链路使用[无人声短示例](../../../examples/vibe-knowledge/README.md)验证，示例不代表正式素材或用户确认。

先读[稿件创作与审查](script_writing.md)，写出完整初稿，从第一幕连读到末幕，先处理跨幕重复、缺少反差或推进的问题，再执行一次统一润色并复核修改处。

再按[共用旁白语义预览](../common/narration_preview.md)实际运行配音流程的切分程序，逐幕生成并汇总语义句组；无旁白版本也必须执行。随后按[字幕初切规则](captions_timing.md#程序初切与人工复核)运行Vibe初切并复核，暂不定时。

**交付与确认：** 同轮交付讲解稿、程序生成的整期旁白语义预览及审查摘要；逐屏字幕草稿须另标类型，不能替代旁白预览。用户确认正文与切分后，按[版本绑定](captions_timing.md#内容确认与版本绑定)保存认可来源；未确认不得进入正式画面制作。

## 2. 先编排连续画面，再落实字幕与时间

<a id="连续事件与节奏先行"></a>
<a id="配合画面落实字幕与时间"></a>

先读[画面组织与动效方法](visual_methods.md)和[动态画面要求](motion_design.md)。在本期唯一的`画面编排.md`统筹全片与幕间接续，再展开当前幕；索引`visual_plan`指向它。按内容查看并复用[完整动态素材库](../../../examples/vibe-styles/README.md)，沿用已有风格确认，不新增逐项选方法或选素材的审批。

当前幕的连续过程及相邻接点自查成立后，按[字幕与时间表](captions_timing.md#配合画面落实字幕与时间)调整分屏、阅读窗口和事件节奏，再生成整期时间表及逐屏预览。首次主题名称须在全片16～19秒完整落定，知识点展示后保留至少1秒阅读停留；登记不能代替实际画面检查。

**通过条件：** 正文、时间表和逐屏预览一致，时间已确定，当前幕有可实现的过程及接续。无字幕段可以保留，但须有内容发展；禁止按读字时间填充无进展的动画。

## 3. 逐幕实现与连续审看

先读[实现与渲染入口](visual_review.md#实现与渲染入口)，按当前编排和时间表实现。背景基调沿用深蓝或蓝绿；新的视觉方向沿用既有风格确认节点及实际小样审看，已确认风格继续有效。

先验证关键连续小样，再制作整幕及相邻接点，最后合并复查全片。具体动作、字号、点题和阅读要求由[动态规范](motion_design.md)维护；正常速度与手机观看尺度的检查、返工及认可范围由[画面验收](visual_review.md)维护。

**交付与通过条件：** 按用户安排交付high质量分幕或整期视频、同版讲解稿和逐屏字幕预览，注明版本与范围。画面组织、动作解释、视觉表现及技术结果分别成立；局部认可不扩大为整片认可。修改节奏或断点后，同步编排、时间表和预览再复查。

## 4. 固定背景音乐与混音

仅在全片画面确认、进入最终高清发布版本时，读取[固定配乐与混音](audio_mix.md)并添加背景音乐。此前所有局部小样、风格预览、分幕及整片画面审看均不加BGM，即使使用high质量或高清分辨率，也不提前配乐。最终版沿用《千年之后》氛围版、音乐25%和动作声100%的系列设置；音乐不足时循环同一素材覆盖全片，不重复询问选曲和比例。

先完成并核验无BGM底片；全片画面确认后，再混音另存最终高清配乐版，供发布前最终确认。底片、循环音轨、增益或画面变化后的处理按该文档执行。

## 5. 独立封面与发布文案

按[封面工作流](cover_workflow.md)完成3:4独立封面，沿用主信息与构图确认、实际图片确认两个已有节点。文案按[Vibe发布要求](release_delivery.md#发布文案)生成，包含标题、正文、标签、总结和章节；封面与视频分别交付。

## 6. 确认高清审片版，生成并验收发布包

完整配乐版获用户确认后，记录原话及该文件SHA256；独立封面也须已确认。按[发布包步骤](release_delivery.md#发布包)执行`vibe:publish`，复制已确认的high审片版、封面及同版文案并验收。

修改文案、封面或索引后运行`vibe:check-release`复查。只有实际检查通过才登记发布包完成；本地发布包不等于公开发布，上传平台另需用户授权。

## 7. 发布后的重建输入

按[Vibe重建输入](published_cleanup.md)核对画面、动作声、音乐及确认原件；保留和删除执行[共同清理规范](../common/published_cleanup.md)，不按版本号整目录删除。
