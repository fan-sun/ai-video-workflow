# Vibe发布后的重建输入

重建链路：

```text
同版 HTML/JS/CSS + 引用素材/字体 + 画面时间表
  → 渲染各幕无声视频
  + 动作音效及其时间安排
  → 各幕带声音视频、整期未加背景音乐底片
  + 原始背景音乐及混音参数
  → 完整混音视频
  → 发布视频
```

共同源码、素材、原件及候选判断按[共同重建清单](../common/published_cleanup.md#共同重建输入与待核对候选)。Vibe 额外保留逐屏字幕和画面时间表、动作音效及落点、实际原始背景音乐、准确的增益、起点、循环、裁切、声道和时长参数。

动作声保留实际 WAV，不仅留生成脚本。音乐循环、裁切、试听和中间混音仅为待验证候选；索引仍引用的音乐文件继续保留，重建依赖必须包含原音乐及准确处理参数。

**当前入口的额外依赖：** Vibe 的 mix 入口读取未混背景音乐的底片；publish 入口复制已确认的审片视频，不负责从 HTML 重新渲染。要删这些 MP4，必须能先从源文件重建各幕、拼接底片并重新混音。仅保留 publish 命令不能恢复被删掉的底片。

Vibe publish 还要求审片文件与 `review_approval.sha256` 一致。重新编码即使观感相同，哈希也可能不同；不能仅为通过检查而改写人工确认记录。因此当前审片原件和确认记录一并保留。

共同删除条件、原件与确认记录保留、独立重建验证及工具暂停状态只在[共同清理规范](../common/published_cleanup.md)维护。
