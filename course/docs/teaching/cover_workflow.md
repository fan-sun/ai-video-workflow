# 课程制作 · 封面制作与验收

本文件维护教学的固定风格代码封面、双尺寸与首帧嵌入；生成和交付时执行[共同封面图片检查](../common/cover_verification.md)。


## 一、进入条件与职责

四幕正式配音已通过技术验收和用户逐幕试听确认、片尾处理与整期时间表完成后，与 [固定视频风格选择](style_preview_workflow.md) 同轮进入本流程。视频方向直接使用长期固定的 A/B/C 预设；每期只为三个方向各生成一个同字母封面候选，用户同一轮分别选择视频风格和封面。

封面与视频选择相互独立：默认推荐同字母组合以保持视觉同源，也允许用户跨组选择。封面选定并通过单独复验后，从同一 HTML 生成 `cover.png` 和 `cover-2x.png`；后续审片未改变主题、标题或整体视觉方向时继续复用，不重复设置用户门禁。发布文案仍在审片版本 vK 确认后按 [发布交付](release_delivery.md) 生成。

本文是教学封面设计和选择的详细规范；共同文件与图片检查只在共用文档维护；主流程见 [SOP](../sop.md)。不为展示候选启动可控浏览器，但必须使用本机无头浏览器真实渲染候选 PNG。

## 二、视觉方向库与内容适配

封面方向以[固定视频风格目录](video_style_presets.html)为准。

| 参考方向 | 视觉特征 | 适用内容 |
|---|---|---|
| 纸本编辑手册 | 暖纸张、批注、印章、倾斜卡片 | 方法论、发展脉络、经验总结、偏人文主题 |
| 技术图解网格 | 米白网格、深蓝框线、克制的黄红强调色；允许坐标、流程、关系网络和分栏布局 | 技术原理、数据结构、模型架构、抽象概念 |
| 明亮模块聚焦 | 浅蓝紫空间、透明聚焦环、彩色模块；中央主题与外围要素形成聚合关系 | 组成要素、信息聚合、认知转变、输入输出 |

每期三个封面方向固定对应视频风格目录：A 为纸本机械，B 为技术路线，C 为明亮模块。三个候选均使用浅色或中性明亮背景，不生成以黑色、炭灰、深蓝等大面积深色背景为主的暗色方向，也不使用霓虹终端式暗色视觉。深色文字、边框和局部图形等功能色可以保留，但必须保证手机缩略图下标题与主体清晰可辨。

生成候选前，AI 读取固定视频风格目录，识别三个方向不可丢失的视觉锚点，再提取本期知识点适合表达的封面语义元素。同字母封面继承固定方向的背景基调、主色系、材质、字体气质和图形语言；封面的主构图可以为缩略图识别重新组织，但不能因此降低语义层级、信息密度或空间覆盖。

三张候选分别以同字母成熟示例为结构基线：A 使用纸本编辑手册，B 使用技术图解网格，C 使用明亮模块聚焦。封面约 70% 稳定继承基线的主要结构、信息密度、语义层级、空间覆盖和视觉锚点，约 30% 根据本期知识点和词语长度调整标题尺寸与换行、模块文案及局部布局。确有内容冲突时可以调整结构，但仍须保持同字母固定视觉系统，并让三张形成不同的主构图和信息组织。

可以缩短模块文字或提高对比度，但不能删掉结构基线中的主要语义节点、关系结构、辅助注释或上下分区，也不能留下只有背景而没有表达任务的大块空白。比例属于设计判断，不做像素级计算；不得复制整套 DOM 后只替换主题文字。


封面候选进入对比页前，必须按当前规范检查中央主题、英文大小写、标题安全区和画面遮挡。

## 三、候选、真实渲染与选择

封面候选存入：

```text
course/episodes/NN-<slug>/cover-options/

A-<semantic-name>.html
B-<semantic-name>.html
C-<semantic-name>.html
compare.html
```

统一要求：

- 候选 HTML 使用 `1080×1440`、3:4 固定 CSS 画布；用户最终选定后，从该 HTML 输出 `1080×1440` 的 `cover.png` 和 `2160×2880` 的 `cover-2x.png`；
- 被讲解的主题词位于画面视觉中心、成为第一视觉层级，并在手机缩略图下清晰可读；
- 英文主题使用现实中最常见的标准写法，禁止用 CSS `text-transform: uppercase` 或手工全大写制造设计效果；`AI`、`GPT`、`BERT` 等本身通常全大写的缩写除外；
- 中文不是必需项；有常见且有助识别的中文译名时，中英文作为一个标题组共同居中，没有常见译名时不强行翻译；
- 装饰英文同样使用正常大小写，除非它本身是缩写；装饰信息不得抢过主题词；
- A、B、C 分别继承同字母视频方向的背景基调、主色、材质、字体气质和图形语言；
- 三个候选均使用浅色或中性明亮主视觉，且不能只是同一构图的换色版本；
- 保留顶部居中红叶和必要的 `深度讲解` 品牌信息；
- 不出现内部期号、幕号、场景编号、调试数字或无关文字；
- 装饰线不得穿过标题或正文；印章、旁注、页脚和重复标签只有在直接帮助理解主题时才保留；
- 三张的主要构图轴、标题容器和信息分布必须明显不同；标题可以融入路线、网络或留白区，不要求使用统一矩形框，也不要求精确落在同一组纵向坐标；

第一轮的 A、B、C 与固定视频风格 A、B、C 一一对应。生成 HTML 后，AI 按[共同代码封面检查器](../common/cover_verification.md#code-cover-check)检查全部三个候选，质检输出放本期 cover-options/qc。比较页和报告要求只按共同文档维护。

三张当前版本均有返回 0 的有效报告后，AI 再查看实际 PNG，并把每张候选与其结构基线并排复核：语义层级、主要元素、关系结构及上中下空间覆盖不得明显减少，不能出现只有大标题和单个底部模块的空疏构图。随后再检查三个候选均未使用暗色主视觉、与同字母视频方向的同源关系、拼写、大小写、非设计性遮挡和缩略图可读性。技术门禁通过不能代替此项结构与密度复核。

固定视频风格目录与本期封面对比页同一轮交付，用户分别选择两个结果，例如“视频 A，封面 A”或“视频 A，封面 C”。封面有两种选择方式：

- 直接回复 A、B 或 C：将该 HTML 分别渲染为正式 `cover.png` 和平台上传用 `cover-2x.png`；
- 回复“封面选择 X 方向，重新生成三种构图”：保持 X 的背景基调、配色、材质和图形语言，生成 `X1`、`X2`、`X3` 三个不同构图 HTML 及第二轮对比 HTML；用户再次选择后才输出两张正式封面。

用户选择后，AI 对选中 HTML 再单独运行一次同一门禁，以该次真实截图生成 `cover.png`；随后使用同一 HTML、同一 `1080×1440` CSS 画布和浏览器 `device scale factor=2` 重新截图为 `cover-2x.png`。必须等待字体和图片加载完成，检查输出确为 `2160×2880` PNG，并将其缩回 `1080×1440` 与门禁截图目检对照，核对标题、红叶、线条和卡片没有缺失、裁切或明显变化。不得把 `cover.png` 插值放大冒充 2 倍渲染；2 倍截图失败时明确报错，不能退回旧尺寸并声称完成。制作索引的 `cover_candidate_styles` 继续使用 A、B、C 到语义方向标识的字符串映射；同字母即表示配套视频方向。封面选择结果记录在 `cover_selection`，与 `selected_style` 分开保存；若进入第二轮，同时记录用户选中的封面方向和最终构图来源。

正式封面保存为：

```text
course/episodes/NN-<slug>/cover.png     # 1080×1440，视频前 0.5 秒与现有发布门禁使用
course/episodes/NN-<slug>/cover-2x.png  # 2160×2880，平台单独上传使用
```

封面采用**独立文件 + 视频首帧**混合模式：平台单独上传时使用 `cover-2x.png`；publish 入口仍使用 `cover.png`，通过 `inject_course_cover.py` 只向第一幕临时构建版注入 `0.0–0.5s` 最高图层，保持现有 1080×1440 视频与首帧验收规格。底层第一幕动画和音频照常运行，封面消失后直接显示当时的原动画状态；不得增加视频时长、移动旁白或修改章节边界。平台若仍提示封面“是截图”，不能断言由分辨率引起：视频前 0.5 秒本就显示同一设计，应另行核对平台规则，不擅自改动视频首帧流程。

封面层必须使用 `class="clip"`、`data-start="0"`、`data-duration="0.5"` 和独立的最高 `data-track-index`。用户的选择结果、正式路径和 `cover_embed.duration_s=0.5` 写入 `制作索引.json`；未选候选在正式封面验收后删除。注入工具重复执行必须保持单一封面层；旧源若已含正确封面层，只允许在构建版重写资源路径。


## 四、布局标记与失败处理

教学候选和选中图均执行[共同检查器的布局标记与失败处理](../common/cover_verification.md#code-cover-check)。选定前全部三个候选须有当前有效报告；选中后单独复验及双尺寸出图继续按第三节。

## 五、交接与保留

正式封面选定、单独真实渲染验收且保存为 `cover.png` 与 `cover-2x.png` 后，保留到画面制作和审片完成。用户确认审片版 vK 后，AI 必须复核主题、标题和整体视觉方向：三者未变化时直接复用两张同源封面，不重复询问；任一变化使现有封面不再准确或同源时，只重新生成、验收并选择受影响的封面，再按 [发布交付](release_delivery.md) 准备高清输出并同步状态。视频封面时间窗、音频不变及全片解码检查由 [渲染验收](render_verification.md) 和发布包门禁负责。清理规则见发布交付；不能在两张正式封面验收前清除候选。
