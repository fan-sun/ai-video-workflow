# 教学画面素材：添加与入库流程

用户要求“把这个片段加入素材库”“从最近几期找好素材”或认可某个动作要积累时，执行本流程。目标是留下可跨主题复用、经过优化的画面结构。一个视频可以零收录，同一结构的原版和换内容示例只算一项。下文路径相对内部项目根目录 `ai-video-workflow/`。

本流程管理教学库 `templates/teaching-scenes/`；Vibe素材沿用独立库，教学视频引用已有Vibe片段时记录原素材，不重复登记成教学新结构。使用已有条目制作视频时执行同目录 `scene_library_usage.md`。

## 1. 确认范围，找到实际来源

先读用户指定文件和已有筛选记录。用户报的秒数是定位线索，按完整动作重新确定起止。用户已明确片段和保留方向时沿用，不重新要求选择同一内容。

批量筛选默认先做最近2～3期，或按用户指定批次执行，每批交付后等待反馈；用户明确要求剩余批次一次做完时按该授权执行，不把它改成今后的默认方式。

从 `course/episodes.json` 核对路线、版本和实际成片；再读取制作索引、整期时间表、视觉节拍表及对应HTML。默认教学成片位于 `pipeline/output/teaching/`；历史项目沿用真实登记位置，可能在外层 `pipeline/output/course/`。内外层期号互不对应，来源记录写明项目根目录和版本，不能只按“第1期”匹配。

没有台账的文件按用户给出的真实路径核实。只有外部参考视频、没有可编辑实现时，先留为参考候选；需要重做时明确记录为重新实现，不能把视频截段称为已具备换内容能力的模板。找不到原片时记录缺失及检查范围，不以源码或重渲染冒充已看过原片。

本批候选、过程图、脚本和反馈保存在 `specs/视频素材积累/<本批名称>/`。只有任务追踪文件维护进度，不把进度表复制到素材说明或每期判断文档。

## 2. 看实际动作，精筛并查重

批量找素材时，先用FFprobe核实原片时长与画幅，按约4～6秒抽全长定位帧，实际打开联系表；结合全部幕次编排和时间轴补查短转场。对有希望的区间做原速连续复查，并查看起点、中段、转折、落定帧。用户指定单个片段时检查该段及前后接点即可，不扩大成整库重审。

保留标准：关掉声音仍能看懂对象关系和动作；更换主题或对象后仍成立；构图、造型、运动、镜头或联动有明确亮点。通用性不靠把原造型简化成普通方框获得。普通文字卡入场、单纯描线、装饰抖动或只能解释原知识点的段落，不为凑数量入库。

同时对照以下现有实现与既往候选：

- 教学库：`templates/teaching-scenes/catalog.json`。
- Vibe自有库：`templates/vibe-scenes/catalog.json`。
- 完整风格和基础动效：`templates/vibe-styles/`、`templates/vibe-motion/`。

查重按“对象关系＋主动作＋镜头或转场”比较实际过程。同一动作只换标题、颜色或道具时合并为参数或变体；确有更好的同类版本，说明替换理由并保留旧来源。文件哈希仅识别相同文件，不能代替动作查重。

## 3. 给用户少量候选，明确保留部分

每期最多约3～5个候选，一批也尽量少量交付；这是审看上限，不是配额。没有合适的就说明零推荐。

候选从动作开始前一点截到结果可看清，通常2～6秒；完整连续过程确需更长时保留必要时长，并说明原因。原速导出，移除全部音轨；不加配音、BGM，不补动作或加速包装原效果。可裁掉外围字幕与栏目，保持纵横比并记录裁切；不能安全去除时保留上下文并注明。

在本批保存 `候选清单.json`、`逐期筛选记录.md`、无声MP4、过程图及一个可播放的候选页面。每项写明：候选编号、来源根目录、期次与版本、整片起止秒、源码及对象ID、通用结构、亮点、限制、相似项和选择状态。

检查视频只有视频流、时长正确、完整解码成功，并实际查看裁切边缘、过程图及播放。分别记录抽帧覆盖、原速播放、助手判断和用户选择，不混写成“已完整审看并认可”。用户尚未选中时停在候选；已明确选中或授权助手筛选入库的范围内继续，不反复确认。

## 4. 选中后优化，再提取独立实现

用户认可结构但指出执行问题时，先修复该结构：对象是否真的迁移，全部非当前目标是否变暗，路径、消息和目标是否同步，接触、遮挡、字形和落点是否连续。保留原候选，新版单独命名并说明改动。

例如 `route-switch` 要核对三次切换的完整链，不能只把第一个目标变暗；`choice-fill` 要让同一词或图标进入可见结果槽，不能淡出后在另一位置换一份结果。优化版连同原片对照交用户复核，已有认可且内容未变时复用；授权已覆盖优化后入库时继续完成，并如实记录授权范围。

提取到工作目录，去掉原课程栏目、固定正文、配音和原timings依赖，保留有效造型、材质、动作及必要依赖。独立教学素材默认1080×1440、30fps、无任何音轨；不绑定某句旁白。只开放实际需要的内容参数，写清固定对象数量、选择位置、路径和字数限制。

每项最终需要以下文件；先在本批工作目录验证，通过后再放入正式目录：

| 文件 | 用途 |
|---|---|
| `index.html`、`timeline.js` | 可编辑画面及单个暂停时间轴，支持直接定位和倒退；沿用 `window.__timelines.main` 注册、`__sceneReady` 就绪等待与 `__sceneSeek(t)` 定位接口 |
| `presets.json` | `original`与`demo`两套真实可运行参数 |
| `assets/`、字体、`gsap.min.js` | 实际用到的本地依赖；正常准备和导出不依赖specs或原期次 |
| `来源.json` | 来源根目录、原片与HTML路径及校验值、版本、原片时间、保留对象、优化内容、能力边界及真实选择状态 |

现有准备器按参数后缀处理图片：以 `Asset` 结尾的值为null或相对项目根目录的本地图片路径；以 `Color` 结尾的值使用六位HEX；其他字段为纯文本，以 `Text` 结尾最多40字，其余最多10字，实际仍须检查排版。沿用已有入口支持的字段类型，不虚构参数能力。

## 5. 换内容验证，完成正式登记

制作一次真正更换对象或环境的demo，不只改标题。例如芯片换电池、词换天气图标；同一结构仍只登记一个ID。检查两版首现、动作中段、落定、连续播放和倒退；检查图形替换、全部目标明暗、路径端点及消息内容。实际导出无声MP4，完整解码，并打开预览核实可用。

通过后同步维护以下位置：

1. `templates/teaching-scenes/<id>/`：保存独立实现、两套参数、依赖和来源。
2. `templates/teaching-scenes/catalog.json`：沿用 `id`、`name`、`duration`、`structure`、`uses`、`source_candidate`、`status` 字段，登记唯一ID、名称、时长、结构、用途、来源候选和真实状态；更新已有ID时不重复追加。
3. `examples/teaching-scenes/index.html`及`README.md`：加入原版与demo预览、替换范围和使用限制；示例MP4放在 `.local/teaching-scenes/visuals/<id>/<original或demo>/preview.mp4`，可从正式源码重建。
4. `examples/teaching-scenes/check-visuals.mjs`和`tests/node/teaching_visuals.test.mjs`：补充该结构关键状态、连续动作、倒退及实际换对象检查；仅被目录循环遍历不代表动作已验证。

沿用 `examples/teaching-scenes/visual.mjs` 准备、导出；具体命令和副本覆盖边界按 `scene_library_usage.md`。修改后执行相关Node测试、该项lint与inspect、两版真实渲染及浏览器核验。整库检查器会重新准备各条目工作副本，运行前确保现有示例视频已生成，不把临时手改放在这些示例目录中。

```bash
node --test tests/node/teaching_visuals.test.mjs
node examples/teaching-scenes/check-visuals.mjs
```

交付可播放入口、正式素材ID、源码位置、时长、适用范围及验证结果；本批记录同步选择、优化与入库状态。没有源码、没有实际换内容验证或检查失败的项保持候选或待处理，不写正式可用。用户只要求本期使用素材时，不自动启动历史批量筛选或新增入库。
