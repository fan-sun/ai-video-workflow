# 课程制作 · VoxCPM 旁白切分与正式化规则


> 本文只适用于 课程制作的 VoxCPM 主链路。讲解稿格式见 [`script_writing_explainer.md`](script_writing_explainer.md)，正式 JSON、配音和 timings 契约见 [`voiceover.md`](voiceover.md)。

## 一、这一阶段的产物

```text
AI 生成讲解稿 → 内容审查 → 单次润色 → 事实、整幕顺读连贯性与可解析性复核（不设置单独用户确认门禁）
→ 四幕确定性切分预演
→ 汇总整期旁白切分预览
→ 可选检查已发布往期视频关联
→ 同轮交付讲解稿、审查摘要与整期预览，由用户同时确认内容与每个整体配音单位
→ AI 按代码保真约束固定四幕正式 JSON
→ 进入 VoxCPM 配音
```

整期用户审阅文件：

```text
course/episodes/NN-<slug>/旁白切分预览.json
```

建议结构：

```json
{
  "act1": ["第一句。", "第二句。"],
  "act2": ["……"],
  "act3": ["……"],
  "act4": ["……"]
}
```

它只展示“哪一段会被当作一次完整配音”，不混入 ID、warning、技术注释或字幕配置。它长期保留用于人工查看和问题追溯，但不是生产输入。

## 二、为什么音频 segment 不能按字幕切

VoxCPM 每个 segment 都会重新起音。按逗号、短语、引号词或字幕行切得太碎，会造成语气悬空、词后停顿和明显拼接感。

- **音频 segment**：一口气能自然读完的完整语气单位，服务声音自然度。
- **字幕 unit**：在父 segment 内进一步拆成短字幕，服务屏幕阅读。

切分预演先确定音频 segment。特殊朗读 `tts_text` 和字幕 `subtitle_units` 在正式化时补齐。

## 三、讲解稿解析前提

正式稿解析格式、逐幕运行、汇总和生成依据核对统一按[共用旁白语义预览](../common/narration_preview.md)执行。本路线固定四幕，具体正文格式仍见[教学讲解稿](script_writing_explainer.md)。

如果 S0 已写在第一幕内，正常预演 act1，不加 `--include-opening`。只有讲解稿存在独立 `## 开场点题` 章节时才增加该参数。

## 四、切分规则

### 1. 一级切分

默认只在强句末标点后切分：

```text
。！？…!?
```

- 右引号、右括号和书名号闭合符跟随前句；
- 不在英文句号 `.` 处自动切分，避免拆坏版本号等内容；
- 分号、逗号和引号本身不是默认切点。

### 2. 长句二切

一级切分后，只有语气单位超过约 36 个可读字符时，才在以下弱标点附近寻找自然切点：

```text
；;，、：,:
```

- 优先形成约 18～30 字的自然段；
- 31～36 字优先保持语义完整；
- 没有自然切点时保留长句并产生 warning，不按字数硬切；
- 不在成对引号、括号和书名号内部二切；
- 不拆术语、固定表达和紧密搭配。

### 3. 合并悬空短片段

不超过约 8 字、以弱标点结尾且无法独立收束的时间、地点、主语或连接成分，在合并后不超过约 36 字时优先与下一段合并。

完整反问、强调句、金句或有明确叙事作用的短句可以独立。短不等于错误。

### 4. 引号与朗读

双引号容易使 VoxCPM 在术语前后产生不自然停顿。正式 JSON 必须：

- `text` 保留引号，保证字幕与画面文字不变；
- `tts_text` 删除中文弯双引号或英文直双引号，不额外插空格；
- 正式化时先使用 `pipeline/02_audio/tts_mappings.json` 对完整术语做确定性替换，并把结果显式写入 `tts_text`；
- 未命中映射且未配置 `tts_text` 时由代码直接使用 `text`；AI 只复核读法，不自由创造替换；
- 映射只匹配完整术语，不得让 `LoRA` 误伤 `QLoRA`、`AdaLoRA` 或 `LoRA-GA`；
- 配音入口拒绝尚未应用的已知映射；未在映射表声明的英文不得删除、翻译或替换；
- 一条音频对应多个字幕单元时，显式填写 `subtitle_units`；
- 不在配音运行时隐式改写，打开正式 JSON 就能看到真实朗读文本。

## 五、ID 与停顿

- 预演默认生成 `g01、g02……`；独立开场可使用 `s0`。
- ID 在本幕唯一，只允许 `[A-Za-z0-9_-]+`。
- 普通句间预演默认 `pause_after: 0.15`。
- 本幕最后一段必须为 `pause_after: 0`。
- 少数转折、强调和场景切换可以人工调整，但不要堆叠细碎停顿档位。

## 六、生成和审阅

讲解稿按 [内容审查与单次润色](script_content_review.md) 完成审查、润色及事实、整幕顺读连贯性与可解析性复核后，AI 必须立即按[共用旁白语义预览](../common/narration_preview.md)逐幕运行程序并汇总，不停下来要求用户审稿。预演采用本文第四、五节的配音语气单位与停顿规则；实际命令、临时文件覆盖范围、执行记录和逐条核对只在共用文档维护。

当前工具按幕运行，因此需将四幕确认候选中的纯旁白文本汇总到整期 `旁白切分预览.json`。同一条交付消息提供 Markdown 讲解稿、简短审查结论和整期预览，明确请用户同时确认核心内容是否准确、讲清、讲顺，以及切分是否合适；不要求逐项资料覆盖证明或另列三处幕间问答。

切分方面重点检查：

- 是否拆开固定表达、术语和紧密搭配；
- 是否出现悬空时间、地点、主语或连接词；
- 是否存在难以一口气读完的长段；
- 是否把需要连读的引号词拆成单独配音；
- 相邻重新起音和停顿是否自然。

### 往期视频关联检查

初次整期切分预览生成后、交付用户确认前，AI 检查：

```text
course/published-videos.json
```

该目录只包含用户已经确认公开发布的 课程视频。本检查的目的，是发现当前讲解中是否存在一个特别自然的知识承接点，不是为每期强行增加宣传语。

判断规则：

- 每期最多推荐一个往期视频；没有高度匹配内容时直接跳过，不向用户报告“没有推荐”；
- 候选必须与当前某个具体知识点直接互补，能帮助观众完成下一步理解或行动；仅仅同属 AI 主题不算匹配；
- 推荐句保持简短、直接，并形成一个完整、可独立删除的配音单位；
- 优先放在第四幕实际应用或边界之后，不插入 S0 点题、核心定义或机制密集段；如果其他位置明显更自然，可以说明理由后提出；
- 不自动写入源稿。AI 在交付初次切分预览时，同时告诉用户：往期视频名称、匹配理由、建议插入的幕、位于哪一句之后，以及拟加入的完整推荐句；
- 用户同意后修改源 Markdown，重新运行受影响幕的切分并覆盖整期预览；用户拒绝则保持文件不变；
- 推荐提案不写入 `旁白切分预览.json` 的技术字段。该文件始终只保存实际候选旁白；用户最终确认更新后的整期预览后，才进入正式 JSON。

读取规模：

- 目录不超过 30 期：读取全部条目；
- 超过 30 期：先只提取全部条目的 `episode`、`topic`、`keywords`，再读取匹配度最高的 5 期 `summary`；
- 当前不设置硬上限；接近 200 期时重新评估关键词检索或分组索引方案。

## 七、问题修改位置

| 问题类型 | 修改位置 |
|---|---|
| 多期都会复现的确定性切分错误 | `build/teaching/course_act_split_preview.mjs`，并增加回归测试 |
| 仅属于当前稿件的措辞、标点或长句问题 | 源 Markdown，随后重新生成预览 |
| 特殊数字、英文、专名或引号读法 | 正式 JSON 的 `tts_text` |
| 一条音频需要显示多条短字幕 | 正式 JSON 的 `subtitle_units` |

不要手改每幕临时 preview 后直接把它当作正式文件。

## 八、固定正式 JSON

正式文件：

```text
pipeline/01_script/<NN-slug>/course_epNN_actN.json
```

正式化顺序：

1. 用户已经同轮确认讲解内容与整期 `旁白切分预览.json`；
2. 确认 errors 为 0，warnings 已逐条判断；
3. 写入最终 `id`、`text`、`pause_after`；
4. 运行 `voxcpm_tts.py --apply-mappings-only --script <正式 JSON>`，将映射结果同步写入父句和字幕单元；
5. AI 复核映射后的读法；未映射英文保持原文，不自由翻译或删除；
6. 校验显示文本和朗读文本都能完整拼回父 segment；
7. AI 复核正式 JSON 与用户已确认的内容及切分一致后，交给配音工具读取，不新增一轮用户确认。

禁止把 `.preview.json` 直接改名后未经检查就用于配音。

## 九、保留与删除规则

长期保留：

```text
course/episodes/NN-<slug>/旁白切分预览.json
pipeline/01_script/<NN-slug>/course_epNN_actN.json
```

整期预览是用户理解配音切分的可读记录；如果正式 segment 后续变化，必须同步更新它。

每幕临时 `course_epNN_actN.preview.json` 在整期预览和正式 JSON 已确认后可以删除，因为它能从讲解稿重新生成。配音工具始终禁止读取任何 preview 文件。

## 十、禁止事项

切分预演及用户确认前禁止：

- 调用 VoxCPM 或 `course_audio.mjs`；
- 生成或覆盖 WAV、timings 和正式 JSON；
- 把字幕行宽当成音频 segment 的切分标准；
- 因为逗号、引号或短词存在就机械拆分；
- 让整期切分预览取代正式 JSON。
