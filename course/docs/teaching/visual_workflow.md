# 课程制作 · 画面转换流程


> 目的：把 `course/scripts/` 中简短的“画面点子”转换为与旁白同步、可渲染、可验收的课程分幕 HTML。

## 一、先区分不会变的约束和可以改的视觉

长期技术约束：

- 1080×1440、3:4 竖屏；
- 每幕独立 HTML、独立构建、独立渲染和 mux；
- 正式音频与 timings 是画面时间轴依据；
- 字幕、画面和旁白必须对位；
- HyperFrames 时间轴必须确定性执行；
- 分幕通过验收后才能拼接版本成片。

分幕从第一次预览起使用 `npm run teaching:review -- <索引> --act N`，与整期共用字幕和完成缓存。修改局部时先用 `--check-only` 检查，再用 `--range 起秒:止秒` 查看受影响片段，定稿后完整渲染本幕；具体命令、支持范围与验收边界见 [分幕制作和局部返工的统一入口](../common/render_verification.md#分幕制作和局部返工的统一入口)。避免每次微调都重渲染整幕，也不能用片段检查代替最终整幕验收。

可以按版本调整的视觉皮肤：

- 背景风格、颜色和纹理；
- 字体、卡片、图标和图形语言；
- 场景构图、转场和动效形式；
- 信息密度和视觉节奏。

## 二、先确认本期视觉风格

确认四幕配音已经完成用户试听，且片尾静音与整期时间表已就绪后，直接从长期固定目录选择 A“纸本机械”、B“技术路线”或 C“明亮模块”：

```text
course/docs/teaching/video_style_presets.html
```

同轮生成并验收本期三个封面候选，用户分别选择视频风格与封面，允许跨组。详细规则见 [`style_preview_workflow.md`](style_preview_workflow.md)。

固定预设图用于选择“固定开头 + 正文视觉风格”。正式画面仍须按本期内容设计对象、关系和构图；所选共享开场母版只在第一幕开头原样复用，并随正式第一幕完成音画对位与渲染验收。正文只继承风格，不继承开场的控制台、框架、状态栏、刻度尺、模块位置或场景结构。

本仓库所有新期次，正文顶部预留 100px 给[视频内章节进度条](video_chapter_progress.md)；视频构建入口按正式时间表统一注入四章标题、进度轨道和移动红叶。画面源只设计其下方的正文，不复制章节栏、固定红叶、额外课程标题或顶线。所选固定开场仍按母版原样播放。

## 三、制作前按顺序读取

### 1. 课程台账和本期讲解稿

```text
course/episodes.json
course/scripts/<期号>-<主题>.md
```

先确认期号、主题、内容分支、当前状态和目标版本，再读取：

- 认知缺口和核心结论；
- 全片核心比喻；
- 每幕、每场景的旁白；
- 每个场景的一句话画面点子。

讲解稿中的画面描述是创意 brief，不是最终设计稿。

### 2. 课程结构和写稿规范

```text
README.md
course/docs/sop.md
course/docs/teaching/script_writing_explainer.md
```

确认：

- 本期概念、受众和认知缺口；
- 每幕承担的叙事任务；
- S0 如何点题；
- 当前画面不能提前展示后面场景的结论。

### 3. 视觉系统

```text
course/docs/teaching/visual_system.md
```

这里定义画布、分层、安全区、字幕、时间轴、构建和版本规则。制作新视觉版本时，先在该文档区分哪些稳定约束继续沿用、哪些视觉皮肤准备更改。

### 4. 技术模板和示例

稳定技术骨架从这里读取：

```text
templates/course-explainer-3x4/index.html
```

只复用画幅、HyperFrames 结构、字体加载、字幕区域、渲染配置和红叶品牌素材。模板原有的背景、配色、卡片造型、版式和动效不是默认视觉风格。

图形及时间轴实现可参考本项目的短教学示例：

```text
examples/context-window/visuals.mjs
examples/context-window/cover.html
```

参考图形、场景显隐和字幕注册方式，实际文案、时间点和场景结构按本期旁白设计。

### 5. 正式音频和 timings

```text
pipeline/02_audio/<NN-slug>/course_epNN_actN_voxcpm/actN.wav
pipeline/02_audio/<NN-slug>/course_epNN_actN_voxcpm/actN_timings.json
```

读取重点：

- `total`：决定 `data-duration` 和 `const DUR`；
- 每个字幕单元的 `start`、`end`：决定字幕时间；
- 旁白语义边界：决定场景切换和动效落点；
- WAV 实际时长：用于 mux 和渲染后复核。

## 四、把一句画面点子拆成场景设计

每个画面点子按下面六项展开：

```text
主体：观众首先看谁
道具：当前讲解涉及哪些可识别物件，各自的外形、关键部件和用途是什么
关系：主体之间是循环、对照、因果还是层级
变化：哪些元素进入、移动、变形、点亮或退出
时间：初始已有哪些内容，哪些信息在对应旁白的几秒首次可见，何时再强调
落点：这个场景结束时观众应该理解什么
```

### 旁白—分镜对照：先编排，再制作

语义节拍表承担分镜作用，必须在写 HTML 或动画代码前完成。保存在 `course/episodes/NN-<slug>/vK/视觉节拍表.md`，标题之后先列进度；制作索引的 `visual_plan` 指向同一份文件，不另建重复编排。不新增用户确认门禁。

每行是一次有含义的视觉推进，直接列出对应的一句、几句或句中原文及正式旁白 ID，不能只填“分析参考”等概括。以下为格式示例，原句、ID、时间和画面须换成本期实际内容：

| 分镜编号 | 旁白 ID 与真实起止秒数 | 对应旁白原文 | 初始可见 / 保留内容 | 主体动作、信息变化与首次可见秒数 | 讲到前必须不可见 | 完成后的关系与理解落点 | 镜头与前后衔接 |
|---|---|---|---|---|---|---|---|
| S0/B1 | `<unit_id> / <start>～<end>` | “先把问题交给助手。” | 提问者与问题 | 讲到“交给”时，问题从提问者移向助手；填写实际触发秒数 | 助手的回答和后续结论 | 看懂问题由谁发给谁；核对接收前后 | 镜头跟随问题，保留助手进入下一分镜 |
| S1/B2 | `<unit_id> / <start>～<end>` | “从候选词中选出一个，补到前文后面。” | 上一步已建立的前文 | 依次展开候选词，在“选出”处选中一个，在“补到”处移入前文；分别填写秒数 | 候选词、选中状态和补全结果 | 看懂候选 → 选择 → 补全的过程 | 沿用前文位置，补全结果留给下一句解释 |

一句旁白不等于一个镜头：短句可共享连续动作，长句可拆成多个分镜，但每行须标出对应原文范围，整体覆盖全部旁白。字幕切行不决定切镜，不按固定秒数平均切场景。时间以正式 timings 和语义边界为准；需要卡词的动作再核对实际音频，不把估算时间当成精确落点。

制作前由 AI 对照正式稿检查原句、ID、时段是否齐全，并确认每段都有具体对象、动作或有理由的保留状态、理解落点和衔接；只写“节点入场”“出现卡片”或场景概要不算完成，须先补齐再写代码。分幕试做或独立小样也必须先完成本次制作范围的对照，不因其他幕尚未制作而省略。

实现时，在场景元素或时间轴代码旁标注相同分镜编号，便于从原句追到具体动作；编号不显示在成片中。缺少对应关系的段落不能登记完成。调整设计先更新相应分镜再改实现，禁止先做画面、后补表描述现状，或为迁就已写代码降低原有表达要求。

### 具体对象的形象与素材

写 HTML 前，在教学视觉节拍表登记主体及对应旁白，执行[共用对象与素材检查](../common/visual_review.md#对象可识别性验收)。对象的出场及关系变化仍按下面教学语义顺序安排。

### 默认随讲解逐步构建

- 场景起点只展示当前旁白需要的信息；未讲到的主体、标签、连线、数值、选择状态和结论保持不可见。可以预留最终布局的空间，但不能用已可辨认的暗色内容代替隐藏。
- 新信息到来时，把相关内容加入已有画面，逐渐形成完整关系。已讲过且仍参与解释的内容应保留；被替换或被否定的内容按语义退出或标记。不要求每句话清空重来，也不机械要求每个装饰逐个入场。
- 区分“首次出现”和“出现后再强调”。移动、放大、高亮可以用于强调已介绍的对象，但不能替代尚未介绍信息的首次出现；开头摆齐、后面轮流动一下，即使动作贴合旁白时间也不合格。
- 例：旁白先讲前馈网络，再讲用专家替换，最后讲加入路由器；画面应先有前馈网络，替换时展开专家并退出旧网络，讲到路由器时再加入路由器及分流连线。不能一开始就出现整套路由图。不同内容依其自身叙述顺序安排，不照搬此例的时间或布局。
- 例外由讲解需要决定：旁白明确要求观察完整结构、全局比较或先总览再拆解时，可以先展示必要整体。节拍表注明该范围、对应旁白和理由，后续新信息仍按时加入；AI 自行判断并记录，不额外等待用户审批。
- 分步标题的每个可见阶段也要可读，不留下孤立标点或半截句子；常驻品牌、背景和已经建立的上下文不必重复隐藏。

### S0 主题词旋转揭晓


概念讲解的第一句固定为“今天要学习的是 XX”。这句话对应一个连续开场动作：

- “今天要学习的是”开始朗读时，画面显示这句引导语；XX 从贴近镜头的超大尺寸开始，整体绕自身竖直轴左右翻转，同时缩小退到屏幕正中央。中文词和英文短语均作为整体，不拆字、不换词，也不沿屏幕平面绕圈；
- 旁白开始读 XX 前完成减速，在词名起点转正并落到最终位置；固定句结束时保持清晰、水平、完整的定格画面；
- 定格帧必须同时读得出“今天要学习的是”和 XX，XX 是第一视觉焦点；旋转过程不得把后续定义、结论或机制提前展示出来；
- 所选共享母版的开场结构、素材和主题词动画原样复用，材质、字体、配色及定格构图不得另写近似替代版本；A/B/C 选择与共享母版见 [固定视频风格流程](style_preview_workflow.md)；正式开场直接写入第一幕源文件并随整幕验收；
- 整句重新配音后，以最终语速的音频核对 XX 的实际朗读起点，并记录声学时间戳或试听定位结果；字符比例估算不能当作精确落点。开场长度随实际配音变化，2 秒只是节奏参考，不强行压缩或截断长词；
- 词名读完保留约 0.2～0.4 秒的自然停顿后进入第一幕钩子；优先利用音频已有留白，不机械追加静音。主题词可以作为上下文短暂保留，也可以随转场退出，不能把定格帧当成持续数秒的静态片头。

### 节拍的覆盖与变化

- 覆盖本幕全部正式旁白 ID；短句可共享连续动作，长句则按含义拆成多个状态。字幕切成几行与画面需要几个动作是两件事。
- 同一场景内也必须推进：预测时逐词补全，纠错时显示错误再更新，比较时逐项展开差异，反馈时让选择信号回流。动作应改变观众正在理解的信息，不能只抖动已有物件。
- 同一场景可以持续十几秒，但不能让所有动画挤在前一秒，剩余时间只换字幕。默认以约 3～6 秒一个可辨认的语义动作作为排查尺度；不是机械切镜频率。主画面连续静止达到 6 秒，须回看对应旁白，补齐遗漏的动作或记录具体的阅读/思考停留理由。
- 文字是标题、短标签和必要示例；定义、流程、对比、因果优先用可操作的物件、图示与空间关系表达。不把整段旁白再搬进主画面的方框。背景纹理、呼吸、字幕显隐以及同一图上改标题都不等于主体解释已经推进。
- 让新信息在讲到它时出现。预训练还在解释预测时，不提前展开助手行为的结论。转场负责清理上一场，下一场开始后仍需按语义分步建立。
- 稳定帧必须可读，动作之间保留观察时间。不得为通过停滞检查添加无关转动、粒子、持续缩放或过密切换。

### 从固定风格到全片

正式第一幕直接复用所选方向的共享开场母版、素材和动画，接入本期正式音频并按 timings 完成落点与正文衔接。开头结束后，母版的具体界面结构全部退出；正文只继承颜色、材质、字形、边界、图形语言和运动气质，按每段叙事分别设计构图。固定风格不是整幕固定底图，正文也不是在开场界面中继续讲解；正式时间轴以语义节拍表为准。


每幕先实现一个完整处理片段（可用 --range 输出技术小样），检查输入怎样进入、主体怎样处理、实际输出怎样变化；内部核对成立后再展开其余节拍。动作未实现时修正画面，不能修改已批准的表达要求去迁就通用文字框。完成后按[共用视觉检查的可执行证据门禁](../common/visual_review.md#教学线的可执行证据门禁)保存实际片段及逐段观察。

## 五、转换示例

### 示例 1：气泡循环

讲解稿：

```text
人和 AI 之间来回的气泡循环，镜头拉开后发现那个圈其实套在人身上。
```

转换：

```text
左侧可识别的人物形象，“你”仅作辅助标签
+ 右侧显示 AI 对话界面的电脑
+ 多个对话气泡和循环箭头
+ 中心关系变化
+ 结论大字“真正跑循环的是你自己”
+ 按旁白边界逐步显隐
```

### 示例 2：人肉验证器

讲解稿：

```text
一个人举着放大镜逐条检查 AI 输出，累得冒汗。
```

转换：

```text
举着放大镜的人物形象，保留手臂、姿态和表情
+ 检查清单卡片
+ 随人物手部移动、逐项检查的放大镜
+ 人工判断计数
+ 检查项逐条点亮
+ 负担累积的视觉反馈
```

### 示例 3：推文传播

讲解稿：

```text
推文卡片浮起，浏览数飞涨。
```

转换：

```text
推文卡片
+ 作者和日期信息
+ 关键词高亮
+ 浏览量数字递增
+ 传播范围扩散
+ 术语定格
```

示例只展示拆解方法，不要求复用同一种构图或视觉风格。

## 六、编写分幕 HTML

新一期源文件写到：

```text
course/acts/epNN_<slug>/actN.html
```

必须先读取[共用合成契约](../common/visual_contract.md)。教学使用课程模板骨架，DUR 和 data-duration 对齐 timings.total；显示格式不反写正式 JSON、WAV 或 timings。

教学正文使用构建入口注入的章节栏和移动红叶，不重复固定红叶、深度讲解或额外顶线；固定开场沿用母版品牌。不显示内部期号、幕号、项目编号、制作标签、调试坐标或画布参数。

字幕由正式 timings 转换，命令与新一期字幕 ID 定点高亮规则统一见 [视觉系统](visual_system.md#八字幕生成与注入)，不在本文重复维护。

生成结果用于构建版 HTML，不覆盖源 timings。

## 七、构建和分幕验收

完成教学语义编排与源文件后，执行[教学渲染与成片验收](render_verification.md)。其中调用[共用技术检查](../common/render_verification.md)及[共用视觉方法](../common/visual_review.md)，本阶段重点对照正式旁白、字幕和教学语义节拍表检查解释顺序；共同方法与命令不在此复制。

## 八、最终拼接和版本处理

所有分幕验收通过后，按 [`sop.md`](../sop.md) 拼接并输出：

```text
pipeline/output/teaching/epNN_<slug>/vK/course_epNN_<slug>_vK.mp4
```

审片版必须再次执行完整解码、幕间交界抽帧、通看和课程台账核对。用户确认具体 `vK` 后，再从同版正式源输出 `_publish.mp4` 高清发布版；工作副本留在 `pipeline/build/`，不进入成品目录。

如果只是计划以后更换背景、形式或动效：

- 先在课程台账备注“可能制作视觉 V2”；
- 当前 V1 继续作为已验收基线；
- 未决定实施前，不提前修改源 HTML 或覆盖 V1；
- 真正开始 V2 时，新建版本并重新完成全部分幕和最终成片验收。

## 九、一句话流程

```text
课程台账与定稿讲解稿
→ 四幕正式音频和 timings 已通过用户试听，片尾与整期时间表已完成
→ 课程结构规范
→ 固定 A/B/C 视频风格目录与本期封面候选，由用户分别选定
→ 视觉系统与技术模板
→ 旁白—分镜对照及覆盖自检
→ 按分镜编号实现分幕 HTML
→ 检查、渲染和 mux
→ 分幕验收
→ 审片版确认
→ 高清发布版
```
