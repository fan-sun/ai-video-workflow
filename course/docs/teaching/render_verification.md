# 教学渲染与成片验收

制作顺序见[教学 SOP](sop.md)。本文件只维护教学的配音、画幅、章节、片尾与嵌入封面要求；技术预检、局部预览、缓存、GPU、解码按[共用渲染验收](../common/render_verification.md)，视觉方法按[共用视觉检查](../common/visual_review.md)。

## 一、验收顺序


```text
读取固定 A/B/C 视频风格目录，按同字母方向生成本期封面，三个方向均不使用暗色主视觉
→ 三张封面真实渲染为 PNG、检查冲突，并生成本期封面对比 HTML
→ 用户分别选择视频风格和正式封面；需要时对选中封面方向再生成三种构图
→ 选中封面单独复验并生成 cover.png
→ 按已选固定视频风格制作四幕构建版 HTML；第一幕开场随正式画面一起验收
→ HyperFrames 静态与布局检查
→ 首次可见状态检查
→ 无声视频
→ mux 分幕音频
→ 分幕技术与画面验收
→ 按幕序 concat
→ 对照整期时间表检查总时长和幕间交界
→ 审片版验收并由用户确认具体 vK
→ 复核已选封面仍与主题、标题和整体视觉方向一致，同时生成含视频总结的同版本发布文案
→ 将正式封面覆盖第一幕前 0.5 秒
→ 从同版正式源创建临时发布构建版，注入封面后输出高清发布版
→ 最终视频解码及时长检查通过后，自动登记索引和台账
→ 自动执行发布版、封面、发布文案、制作索引、课程台账五方核对
```

任何一幕技术检查失败，都不能进入整期技术拼接。
技术通过允许拼接待检查的整片，但只有[视觉证据门禁](../common/visual_review.md#教学线的可执行证据门禁)通过后才能登记视觉合格并交用户审片。review_output 只表示文件已生成；review_technical_status、visual_review_status、review_approval 分别表示技术、助手复核和用户确认。高清发布入口及独立发布检查会再次校验后两项，不能以手写的完成状态放行。

用户已对当前整片明确给出最终视觉接受时，按上述门禁的 accepted_by_user 路径继续；保留助手未完成检查的真实范围，不要求用户重复审片，也不把用户结论登记为助手已完成连续审看。


四幕配音已通过用户试听、视频风格与封面已分别选定且四幕画面源完成后，由 AI 运行 `npm run teaching:review -- course/episodes/NN-<slug>/制作索引.json`，不要求用户手动执行逐幕命令。

命令从已经确认的四幕 WAV/timings 开始，自动准备独立构建目录、生成并注入字幕、依次执行 `lint`、`validate`、`inspect`、标注元素首次可见检查、standard 渲染、WAV 封装、逐幕完整解码、配置的主体停滞检查和整期拼接，生成审片版：

```text
course_epNN_<slug>_vK.mp4
```

审片逐幕使用 standard；资源和串行要求按共用渲染规范。分幕预检、局部预览及缓存复用使用[统一入口](../common/render_verification.md#分幕制作和局部返工的统一入口)。

## 二、教学分幕检查

开始渲染前执行共用技术预检及首次可见检查。教学 data-duration、DUR 与正式 actN_timings.json.total 一致，输出为 1080×1440、30fps；正式音轨与 WAV、timings 对齐。完成后执行共用媒体核验及视觉检查，再检查：

- 当前画面与当前旁白一致，没有提前剧透后面内容；
- 关键词高亮、标题和顶部课程条内容正确；
- 教学线所有新期次按[视频内章节进度条](video_chapter_progress.md)核对封面及固定开场无章节栏、正文首帧显现、两行截断、红叶与进度同速、四幕边界连续；旧正文顶线和分割线残段不得露在轨道下方；
- 每幕至少抽查一条包含关键词高亮的长字幕；允许自然分成两行，但不得因 Flex 分块或普通换行产生孤立单字行；
- 动效帮助理解，没有抢旁白注意力；

### 教学语义推进与运动配置

对照视觉节拍表的每个旁白 ID，核对动作前后及完整片段，确认新信息在相应讲解处进入、逐步形成关系。提前完整展示必须有按教学视觉流程记录的理由，不能仅因持续移动或高亮放行。

每幕必须设置 acts[].motion_check 的主体 crop 与 max_still_s，默认 6 秒。检测执行及证据边界按共用渲染规范。必要阅读或思考停留在节拍表写准确起止、内容及理由，按实际需要调整并复核；6 秒不是固定切镜间隔，1 秒正常片尾停留不受影响。

### 片尾 1 秒收尾检查

本项检查教学第四幕和整期结尾；工具兼容六幕时作用于实际末幕。所有教学新期次执行：

- `act4_timings.json` 最后一个 phrase 的 `gap` 为 `1`，且 `total - phrase.end` 精确为 1 秒；
- `act4.wav` 实际时长、第四幕 `data-duration`、`const DUR` 与更新后的 `timings.total` 一致，只允许正常毫秒或帧取整尾差；
- 静音采样允许起点存在不超过 20ms 的 WAV 边界量化残留；高清发布版考虑一个 AAC 编码帧，允许不超过 30ms 的起点残留。容差之后的剩余片尾必须保持静音，持续有声必须失败；
- 最后一句字幕在 phrase 的 `end` 时消失，后续 1 秒不再显示字幕；
- 最终结论画面在这一秒内持续可见，不切黑、不离场、不出现新信息；允许已有元素做轻微呼吸动效，但不能形成新的视觉事件；
- 至少抽取“最后一句结束后约 0.2 秒”和“视频结束前约 0.1 秒”两帧，确认两帧均为有效收尾画面。

## 三、最终拼接验收

各幕通过后按幕序拼接，使用带期号和版本的正式输出路径。总时长与整期时间表一致，时间表已含末幕 1 秒片尾；执行共用整片媒体核验、全部实际幕间接点及正常速度全片审看。教学默认四幕，对三个交界逐一检查；兼容六幕时按实际边界全部检查，不漏后续接点。

## 四、用户确认审片版本

完成技术检查后，用户必须正常速度通看审片版，并明确确认具体版本，例如“确认 v4”。如果仍需修改旁白、字幕、画面、动效或品牌信息，继续生成新的审片版本；此时不要提前生成高清发布版。

用户确认的是内容版本，不是“某个低码率文件以后直接扩码率”。确认后应锁定该版本使用的：

```text
四幕正式 JSON
四幕 WAV 与 timings
四幕画面源 HTML
构建和字幕注入配置
```

## 五、高清发布版输出与验收

确认 `vK`、复核已选正式封面仍有效并准备第一幕 0.5 秒封面层后，生成同版本发布母版：

```text
pipeline/output/teaching/epNN_<slug>/vK/course_epNN_<slug>_vK_publish.mp4
```

发布版内容必须与已确认审片版一致，版本仍为 `vK`；唯一允许增加的是用户从三张候选中选定的前 0.5 秒封面层。应从同版正式 HTML、WAV 和 timings 创建临时发布构建版，只在第一幕构建版注入封面后重新高质量输出，正式源不改写；禁止对已经明显压缩的审片 MP4 简单提高码率并宣称清晰度得到恢复，也禁止在高清成片完成后追加封面并二次编码整片。

publish 入口先核验正式封面并同步待发布状态，再串行生成四幕 high 无声视频，拼接后直接复制已确认审片版的 AAC 音轨，不重新编码音频；随后完整解码、核对实测时长与正式时间表，自动回填真实输出路径、版本与正式时长，再执行发布门禁并生成 `qc/report.html`。内容签名、输出哈希与验收配置一致且完整解码通过的分幕可以安全续跑；否则自动重建该幕。

本地高清发布母版基准：

- 1080×1440、30fps；
- H.264 Main 或 High Profile、`yuv420p`；Profile 必须属于制作索引 `video_profiles` 允许值；
- 从同版 HTML 使用 `--quality high --workers 2 --browser-gpu --gpu` 重新渲染；
- GPU 和失败处理按[共同资源规则](../common/render_verification.md#gpu-与资源使用)；
- AAC、48kHz、单声道、192kbps；
- 启用 `faststart`，便于网络端渐进加载。

CPU x264 预设仅作为无 NVENC 机器的备用说明，不能在当前生产机上自动启用；具体编码背景见 [`render_presets.md`](render_presets.md)。码率不是唯一清晰度标准；发布版还必须检查小字号、细线、网格、纸张纹理、渐变和转场运动中是否出现糊边、色块或明显压缩噪点。

`course_video.mjs publish` 和 `check_course_release.mjs` 自动执行：

1. 执行[共同媒体核验](../common/render_verification.md#分幕与整片媒体核验)；
2. 审片版与发布版解码音频 MD5 一致性检查；
3. 封面起点、封面结束前和正文第一帧 SSIM 检查；
4. 四幕中点与三个幕间前后帧抽取到 `qc/report.html`；
5. 与审片版核对内容、字幕、音画同步和场景顺序；
6. 输出登记在发布包检查之前执行，细则见 [发布交付](../common/release_delivery.md)；该登记不改变公开发布状态。

## 六、封面与发布包交接

进入高清渲染前，核对视频风格确认阶段已按 [封面流程](cover_workflow.md) 完成所有候选的真实渲染门禁、用户选择和选中封面的单独复验，并确认后续审片未使主题、标题或整体视觉方向失效；没有有效的正式 `cover.png` 不能继续。封面设计与候选检查细则只在该文档维护。

## 七、版本与发布一致性门禁

发布文案格式、章节、期号与版本一致性、台账状态、发布授权和已发布目录登记，统一按 [发布交付](../common/release_delivery.md) 执行。publish 自动调用发布包检查器；后续修改配套产物时由 AI 独立重跑该检查。

发布后保留输入和清理范围按[教学重建输入](published_cleanup.md)及[共同清理规则](../common/published_cleanup.md)，不在本文件另设删除清单。
