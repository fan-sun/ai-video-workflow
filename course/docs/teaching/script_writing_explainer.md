# 课程制作 · 概念讲解稿规范


> 本文负责 课程制作的教学与热点词的概念讲解。完整生产顺序见 [`sop.md`](../sop.md)。

热点词按本规范讲清本期核心问题，按需要展开机制、用途和关键条件；内容取舍遵循[内容审查](script_content_review.md)，不追求主题全覆盖。

## 一、产出和完成标准

定稿写到：

```text
course/scripts/NN-<slug>.md
```

讲解稿完成必须同时满足：

- 期号、主题和内容分支已登记到 `course/episodes.json`；
- 认知缺口和核心比喻已经确定；
- 正文按四幕、分场景编排；
- 每个场景包含一行旁白和一个粗画面点子；
- 讲解稿已经通过 [`script_content_review.md`](script_content_review.md) 的内容审查；
- 全部旁白已经使用项目本地 `.agents/skills/copy-editing/SKILL.md` 单次润色；
- 旁白文本已经复核事实边界、知识顺序、整幕顺读连贯性和可解析性；
- 文件结构能被 `build/teaching/course_act_split_preview.mjs` 正确读取。

讲解稿初稿完成后，按 [内容审查与单次润色](script_content_review.md) 做一轮内容检查，有实质问题时局部修正，再做单次轻量润色与通读、可解析性复核。随后立即进入 [切分预演](act_split_rules.md)，由用户同轮确认讲解内容与切分，确认后才固定正式 JSON 并配音。视频风格在四幕配音试听确认后选择，写稿阶段只写粗画面意图。

## 二、动笔前先定两件事

- **核心认知缺口**：本期要帮观众弄懂的一个问题，不预设观众一定持有某种误解。
- **核心比喻**：一个普通人能复述、并且可以贯穿全片的比方，例如“裁判与教练”。

后面的定义、机制、案例、用法和边界都要服务这两件事。一个场景如果既不推进认知缺口，也不强化核心比喻，就应考虑删除或合并。

## 三、S0 点题和钩子

S0 是第一幕开场的一部分，不是正片前面额外增加的固定词卡。连续开场应完成：

1. 第一句使用“今天要学习的是 XX”，其中 XX 必须替换为本期概念名；
2. 用一句人话给出最短定位；
3. 立即接入问题、反差、困惑或常见误区。

开场第一句只承担点题，固定为“今天要学习的是 XX”。XX 优先使用目标观众熟悉、自然且适合画面定格的概念名；需要补充英文名或别名时，放到后一句，不把双语名称都塞进固定句式。

写稿、润色和切分预览都须原样保留“今天要学习的是 XX”；不在概念名之前增加描述、故事或悬念。

概念名应在固定开场句结束时明确。点题完成后，旁白和画面继续推进第一幕钩子，不能停在只有光环呼吸、轻微缩放或装饰节点运动的固定标题卡上。

推荐直接把 S0 写在 `## 第一幕` 内。若将开场单独写成 `## 开场点题` 时，后续预演 act1 才需要使用 `--include-opening`。

## 四、四幕骨架

| 幕 | 叙事任务 | 必须完成 |
|---|---|---|
| 第一幕：场景与问题 | S0 点题后进入观众熟悉的具体场景 | 建立本期要回答的问题或观看理由，不必预设误区，不重新报一次概念名 |
| 第二幕：它是什么 | 给出人话定义，让核心比喻登场 | 观众能够用一句话复述概念 |
| 第三幕：怎么运作 | 按机制自身的顺序讲清怎么运作，不预设环节数量 | 每段只推进一个新认识，用比喻解释机制 |
| 第四幕：怎么用与收束 | 承接第三幕，讲本期需要的用途、起点或关键条件 | 回应本期核心问题，平实收尾，不强求补齐所有局限 |

讲清顺序靠内容承接：先发生什么、再发生什么、于是什么，由事实和机制本身连起来。编号能帮助理解真实步骤、分类或对照时可以使用；只有编号在代替内容关系、让旁白像念清单时才删改，不按词语判退。

收尾目标是让观众获得一个能复述、能迁移的认知框架。禁止突然价值升华、营销式口号或无关互动话术。

幕与幕之间应自然连贯，让观众知道下一段与前文的关系。可以用问题，也可以直接陈述，不强制把每幕首尾写成问答。与当前讲解无关的免责、术语澄清或数字应删去或留在资料备注，不为过渡硬塞知识点。

## 五、讲解稿必须使用的可解析结构

预演工具按文本结构提取旁白，不理解自由格式。建议使用下面的最小结构：

```markdown
# 深度讲解 · 第 NN 期 · <主题>


## 第一幕 · <幕标题>

**S0–S1 · <场景标题>**
旁白：<这一场景的完整口播，必须写在同一物理行>
画面：<主体、关系、动作和状态变化>

## 第二幕 · <幕标题>
```

解析硬要求：

- 幕标题必须以 `## 第一幕`、`## 第二幕`、`## 第三幕`、`## 第四幕` 开头；后面可以追加副标题；
- 旁白必须顶格写成 `旁白：...`，使用中文冒号；
- 一条 `旁白：` 必须占一个物理行，不能把同一段口播折成多行；
- `画面：` 不参与旁白提取，但应紧跟对应旁白；
- 场景编号和标题用于人工阅读，不作为预演工具的切分依据；
- 独立的 `## 开场点题` 不会自动进入第一幕，必须在预演 act1 时显式增加 `--include-opening`。

## 六、每个场景怎么写

每个场景只做一件主要的认知工作：

```text
一句或一段自然口播
+ 一个能够解释当前旁白的画面隐喻
+ 一次清晰的信息推进
```

旁白要求：

- 像懂行的朋友解释，不像老师训话或卖课；
- 只解释当前理解必需且受众尚不熟悉的术语，常识和前文已交代的信息可以默认；
- 多用具体过程、对照和能想象的比喻；
- 不堆参数，不替厂商宣传，不把概念包装成“神器”；
- 不为了 TTS 预先按逗号切碎，先保证自然口播；
- 特殊数字、英文或专名的朗读写法留到正式 JSON 的 `tts_text` 处理。

初步画面只写：主体、关系、动作、状态变化和结论落点。不要在讲解稿里写具体秒数、CSS、SVG 路径或动画参数；精确时间属于 timings 和画面制作阶段。

画面点子涉及具体对象时，写出能看见的物件和动作，例如“配送车载着包裹沿路线前进”“人物把材料摊在工作台上”；不能只写“出现物流模块”“出现工作台卡片”来代替具体形象。抽象信息可用节点或图表表达，详细选择见 [具体对象的形象与素材](visual_workflow.md#具体对象的形象与素材)。

## 七、长度和场景数量

- 概念讲解的常规目标时长为 4～6 分钟，这是规划区间，不是必须填满的配额；
- 如果本期核心问题能在 4 分钟以内讲清，可以正常缩短，不增加重复案例、空泛总结或无关背景来凑时长；
- 如果主题确实复杂，预计 6 分钟仍讲不清，AI 必须在写稿前指出需要展开的复杂点、预计时长和不能压缩的原因，提醒用户后再继续；
- 中文口播可先按约 4～4.5 字/秒估算；
- 字数只用于初步估算，最终时长以正式 VoxCPM 整轨音频实测为准；
- 场景数量按内容需要决定，不把“约 20 场景”当成硬指标；
- 压缩时按本期核心问题取舍，保留支撑理解的定义、关键机制和结论，允许省略分类分支、旁枝和非关键条件。

如果一句太长且没有自然切点，应先改写讲解稿，而不是让后续切分工具硬拆。

## 八、进入切分预演前的检查

- [ ] 课程台账中的期号、主题和分支正确
- [ ] 四幕标题能被预演工具识别
- [ ] 每个场景都有顶格、单行的 `旁白：...`
- [ ] S0 已在第一幕连续完成，或明确采用独立开场结构
- [ ] 开场第一句严格使用“今天要学习的是 XX”，XX 已替换为本期概念名，英文名或别名放在后一句
- [ ] 认知缺口和核心比喻贯穿全片
- [ ] 本期核心问题讲清，用户指定重点保留；按 `script_content_review.md` 判断必要信息，不要求资料全覆盖
- [ ] 全篇顺读自然，幕间没有明显跳题、重复或为衔接硬塞知识点，结尾回应前文
- [ ] 实际采用的核心事实、研究、数据和引语有依据，影响结论的必要条件没有丢失
- [ ] 全部旁白已完成项目本地 `copy-editing` 的单次润色，且没有混用其他写作 Skill
- [ ] 讲解稿已复核事实边界、知识顺序、整幕顺读连贯性和可解析性，可立即生成切分预览

完成检查并解决实质问题后，AI 不停顿询问，立即进入 [`act_split_rules.md`](act_split_rules.md) 的切分预演；交付 Markdown 讲解稿、简短审查结论和整期预览后，由用户在同一门禁确认内容与切分，确认后才固定正式 JSON。
