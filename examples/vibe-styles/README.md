# 20种风格素材库

20种完整场景与绘制源码已放在本仓库。可直接复制其中的空间、材质、对象运动和特效实现，按本期内容调整；保留有效细节，不先重写成几个基础图形。示例的题材、构图、文字和十秒时长不作为制作模板。

## 打开与选择

在仓库根目录运行：

```bash
npm run preview:styles
```

打开终端地址，默认 http://127.0.0.1:5591/ 。左侧切换20种原版，画面底部暂停、拖动进度，也可以单独打开。服务只监听本机；三维场景首次加载可能较慢。原版实时预览不含配乐和导出器额外叠加的多子帧运动模糊。

## 源码位置

- [完整场景](../../templates/vibe-styles/source/styles/)：20个目录，含原场景HTML及媒体。
- [公共绘制库](../../templates/vibe-styles/source/lib/)：数学、Canvas、WebGL与材质实现。
- [接入文件](../../templates/vibe-styles/bridge.js)：单条暂停时间轴、素材准备等待、片段起点及可选字幕。

预览、准备及渲染均只读取仓库内文件，不依赖specs、外部参考项目或本机其他工程。示例文字和画内署名属于原例内容，制作本期画面时须按实际内容处理；文件内许可单独保留。

## 准备、渲染与接入本期

先试原样技术片段：

```bash
node --env-file-if-exists=.env examples/vibe-styles/run.mjs prepare 03
node --env-file-if-exists=.env examples/vibe-styles/run.mjs render 03
```

默认生成`.local/vibe-styles/03-flat/`，含独立HTML、依赖和设置；render导出1080p、30fps、high、2个worker的无声MP4。构建会等待字体及异步素材就绪，不运行原预览的独立时钟。字幕与画面共用一条时间轴，支持倒退定位。

可在本期期目录建立设置JSON，作为命令第三个参数：

```json
{
  "outRoot": "course/episodes/NN-topic/style-work-v1",
  "start": 2,
  "duration": 3,
  "sourceConfig": {},
  "captions": [
    {"start": 0.3, "end": 2.4, "text": "本期已确认的字幕"}
  ]
}
```

start是原例内起点，duration是截取长度，范围位于原例0—10秒；保持原动作速度，不靠整体拉伸凑时长。sourceConfig沿用对应源码的Reel.cfg字段，各风格字段不同。captions使用片段内时间，按本期已复核的逐屏时间表填写；工具提供80px稳定字幕区并在显示层去标点。默认没有字幕，不自动生成或改写正文。

使用原实现制作本期的推荐方式：

1. 准备到本期期目录的独立版本，先看完整原例，再决定保留哪些运动、材质与空间联系。
2. 在这个工作副本中改成本期对象与过程，重新安排必要标签、字幕和接续。示例内的小字、原题材和十秒时长不会自动满足本期要求。
3. 修改后的副本用现有渲染入口导出：`node --env-file-if-exists=.env build/common/hyperframes_hidden.mjs render <副本目录> --output <片段.mp4> --quality high --fps 30 --workers 2 --gpu`。**不要再对同一目录运行prepare或本库render，它们会按库内原例重新生成文件，覆盖手改内容。**
4. 将完成的片段放入本期素材目录，通过现有`visual_assets`登记；在实际整幕HTML根节点中作为视频素材安排出现时段，与本期时间表、字幕和动作声接续。也可将绘制函数迁入整幕源码，但整幕只保留既有一条时间轴，不能同时再运行原预览循环。
5. 在实际整幕中验证字幕覆盖、标签可读性及前后接点，依照[Vibe画面验收](../../course/docs/vibe/visual_review.md)审片。

把原例所有字改大不等于满足手机观看要求。观众需要读清的名称、数字和解释须按[正式字号及标注规则](../../course/docs/vibe/motion_design.md#手机观看字号)重新布局。默认背景、声音和关键词规则继续沿用当前SOP；本库不自动改变整期风格。原例cues仅作为动作声落点的参考，不能据此自动给所有运镜加声音；音乐及混音仍走现有流程。

## 验证范围与复查

六种优先素材已通过当前接入方案的定位及倒退检查，并实际导出10秒1080p/30fps验证片；本机预览中有“查看已渲染MP4”按钮。prepare/render目前只开放这六种。其他14种完整源码和原版预览已保留，首次用于生产时再适配其时间轴及素材准备方式，并验证实际片段。技术验证不表示原示例可以直接当成正式视频，也不等同于用户审片确认。

```bash
node --test tests/node/vibe_styles.test.mjs
node --env-file-if-exists=.env examples/vibe-styles/check.mjs
node --env-file-if-exists=.env examples/vibe-styles/run.mjs render 09 examples/vibe-styles/render-settings.json
```

浏览器报告和对照截图在`.local/vibe-styles/check/`；上述render-settings将独立渲染放到`.local/vibe-styles/renders/`。检查统一双方字体配置，比较1、4.5、7.5秒状态及倒退、字幕清除。原版拼贴自身在重复定位时存在细小像素差异，因此记录平均色差与明显差异像素占比，不把通过写成逐字节一致。视觉对照上限为平均通道差0.15/255，单像素通道差大于12的占比0.1%；仍须检查实际输出，不能用这个阈值替代正常速度审看。

字体使用项目内的Noto Sans SC和随库保存的Noto Serif SC；西文字体与系统回退仍须在本期环境核对。17编辑风的纸纹在适配副本中固定随机种子，避免多个渲染worker各自生成不同纹理；保留原来的纸纹算法，原版文件不改。复杂WebGL材质先测实际片段的画质与耗时，不从浏览器能播放推断正式渲染速度。长源码文件的lint长度提示可说明原例保留原因；字体缺失、初始化失败和空白帧不能忽略。
